按本题指标读取[指标定义](references/metric-definitions.md)的公式和边界，以及[数据映射](references/data-mapping.md)的源与缺口。用实际加载工具的path和offset/limit读取，未加载段落不视为已知。页面简报仍只用已加载页面证据，技能步骤不自动授权补数。

先选本题业务分支，不遍历全部指标。已有异常对象和偏差可直接诊断；交接对象、版本、截止和证据引用，不重复查相同数据。

### 任务目标：

从异常指标定位主要影响对象，沿公式构成、供需约束、业务过程、异常事件及原始记录查证。完成标准：异常可量化，贡献对象可定位，原因链可回溯，证据状态明确，数据不足有具体核查问题，建议有验收条件；不得只解释汇总变化或罗列通用原因。

### 所需知识与数据：

`<指标定义参考中的共用知识、业务公式和阈值、主数据、计划版本、订单商品行及状态、当时库存与批次可用状态、供需匹配、生产/采购/调拨记录、出库/运输/签收节点、改单/作废/审批日志、任务台账及验收记录>`。

事件证据至少包含业务实体或Case ID、事件名称、事件时间及责任角色。跨环节判断需对象关联和时间关系；同基地同期汇总只能作为线索。技术映射缺失时先列业务数据需求，后续补充后再执行对应查询。

先按[数据映射](references/data-mapping.md)选择对应指标的表和字段，保留附件已给的关联与过滤；不得把缺少部分字段概括为完全没有映射。对应业务稿已核实源的库存采用 `inv_qty`、`age_days` 及同一 `dt`，生产采用 `deliv_qty`、`order_qty`，预算采用 `BQ_XSE`、`YS_XSE`，其他指标按各自条目核实；不能把这些字段套用到其他模型。指标汇总字段不等于根因证据，跨过程诊断仍需补对象关联和事件记录。

### 输入内容：

用户问题、标准指标、对象范围、统计期间、数据截止、比较基准、计划版本、已知异常及证据、可用数据与工具、输出用途。优先复用已确认信息及预测分析结果，避免重复取数；关键歧义集中澄清。

### 工作步骤：

1. **明确问题和契约。**确定指标、对象、分子分母、单位、时间、版本、排除规则、阈值及周期聚合。满足率/准交率、准确率/达成率、已开/未开缺口分别处理。字段缺失标记映射待补充，业务冲突单独确认。
2. **取得数据并校验。**按实际权限和能力取必要数据，校验零发货和未交付覆盖、重复、单位、关联放大及汇总勾稽。快照不跨日累加；企业年度月均按专有规则保留。未结期间比较同截止范围，样本不外推。
3. **量化异常与贡献。**列实际、可比基准、绝对差异、相对变化或百分点差；按缺口量、偏差量、超时影响、超龄库存量或金额贡献排序，兼顾持续性。说明贡献分母，重叠原因及不同维度不可直接相加。
4. **逐层诊断。**按“结果指标→公式构成与重点对象→供需/执行约束→业务过程→异常事件→原始记录”查证，深度由实际证据决定。主要入口如下：

   | 问题类型 | 诊断入口与关联证据 |
   |---|---|
   | 订单满足、已开订单缺口 | 订单商品缺口→当时库存及供给匹配→生产/调拨/可用状态→相关事件；未发货不自动证明因缺货 |
   | 未开订单缺口 | 未开需求池→共享库存分配→占用及开单状态；不可对每张订单重复扣同一库存 |
   | 准交、超时、预警 | 应交订单池及适用时效/规则→节点耗时→延误或规则命中事件；整单去重，核查未交及拆单 |
   | 改单、作废 | 原订单及变更版本→锁定窗口/作废条件→数量和时间变化→原因及操作记录 |
   | 库存、大日期、新鲜度 | 同快照SKU批次→生产日期和出入库→需求消耗及分配→积压形成事件 |
   | 可发货天数 | 可用库存和计划日均需求分别拆解→状态、版本、调拨系数→供需形成机制 |
   | 生产达成 | 生产单及产线未达成量→物料、产能、停机、换线、质检→执行事件；影响订单需匹配证据 |
   | 预测或提报准确率、达成率 | 对应主体版本及单品偏差/进度→客户、区域及SKU→调整、需求释放、限供及履约证据 |
   | 销售预算达成 | 同期不含税收入和预算→销量、价格及结构→客户和业务事件；量价分解需对应明细 |
   | 任务数、任务完成率 | 去重任务池及到期/验收规则→责任角色、逾期和依赖→状态及验收事件 |

5. **检验原因和影响。**记录对象、现象、实体关联、事件及结果时间、机制、支持与反证、影响量及方法。事实有原始记录支持可标已验证；因果结论还需合理时间顺序、机制及替代解释核查。可用对象级重放估计消除约束后的影响，但情景估算不冒充实际效果，无法量化时明确缺口。
6. **设置数据断点。**无明细、关联、时间记录、权限或真实工具支持时，停止该分支并列明“停在哪层、已证明什么、不能证明什么、缺什么、找谁取得、取得后如何验证”；继续其他独立分支。业务公式可先编写，不用假数据补齐根因链。
7. **提出行动并自检。**已验证原因形成处置及预防建议，待验证解释形成核查建议；列对象、动作、依据、责任角色、前提、建议时限/触发条件及验收指标。联系人不自动等于执行责任人。检查数字、来源、状态、重叠贡献及执行授权，交付可支持部分和限制。

### 输出要求：

按以下格式输出，简单问题可缩减无关部分：

1. **核心结论**：直接回答问题，说明证据状态与最深确认层。
2. **范围与口径**：指标、对象、期间、截止、单位、版本、公式、来源和覆盖限制。
3. **异常及贡献**：基础量、比较差异、主要对象与影响，明确去重和贡献分母。
4. **原因证据链**：`层次｜对象｜现象/原因｜关联实体和事件时间｜证据与来源｜证据状态｜影响量及方法`。
5. **数据断点**：`停止层次｜缺失数据｜受影响判断｜建议获取角色｜具体核查问题｜验证方法`。
6. **行动建议**：`类型（核查/临时处置/预防）｜对象｜动作｜依据｜责任角色｜前提及建议时限｜验收指标和规则｜执行状态`。

证据状态采用：`verified` 已验证、`supported_unverified` 有支持但待验证、`hypothesis` 业务假设、`data_missing` 数据缺失、`definition_conflict` 口径冲突。未知数值写“待补充/不可计算”，需要结构化输出时用 `null`。前端需要时按上述业务字段结构化，不能省略证据和数据断点。所有建议与实际执行结果分别标注。
