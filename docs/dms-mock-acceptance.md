# DMS 模拟回写验收（Issue #23）

本页记录独立 GEA 插件的 DMS mock 验收。依据用户提供的《销售计划_审批状态码统一口径_V1.2》§6：只回写状态 5；成功后同步设置状态 10、SYNCED、finished_at；失败保持 5；Z 单拆分追加/追减；PLANE_NUM 使用源 plan_id。用户明确要求 DMS 只做模拟效果，其他业务继续使用真实 GEA。

## 实现范围

`src/mock-dms.ts` 提供内存模拟接收方、回执和状态回读。`demos/dms` 为独立演示页，使用合成的 MOCK 计划，不接入真实审批工作台，不加载登录配置、Token 或服务账号，不调用 GEA/DMS 接口。页面设置 `connect-src 'none'`。刷新或重置会清空模拟状态；本实现不声称具有跨进程恢复或真实持久化能力。

旧 `MockSalesPlanAdapter.acknowledgeDms` 的直接改状态入口已删除，DMS 验收统一由新模型负责；原审批/SAVE mock 仍保留原职责。

## 复现

在插件仓库执行：

```sh
node scripts/build-dms-demo.mjs
python3 -m http.server 3202 --bind 127.0.0.1 --directory .runtime/dms-demo
```

Chrome 打开 `http://127.0.0.1:3202/`。计划类型支持 Y/XN/DC/FC/JD/TM；单据类型支持 M/Z。点击“模拟品类终审”后进入 5，再选择回写场景。切换类型会重置数据。

| 场景 | 预期状态与证据 |
| --- | --- |
| 成功 | 5 → 10；SYNCED 和完成时间同时出现；记录 DMS_SYNC |
| 明确失败 | 保持 5、FAILED、无完成时间；记录失败；选成功后按原键重试 |
| 接收前超时 | 保持 5、UNKNOWN；禁用重投；对账确认缺报文后才允许原键重试 |
| 已接收但回执丢失 | 保持 5、UNKNOWN；对账回读已有回执直接完成，投递次数不增加 |
| Z 单仅追加已接收 | 对账后仍为 5，只有一笔回执；原键重试补追减，实际入库总数为 2 |
| 重复回执 | 状态仍为 10；完成时间不变；不重复记录 DMS_SYNC 或实际入库 |
| 错误来源/旧版本/冲突回执 | 批次校验失败，不部分更新回执，不改变终态 |

## 报文与来源规则

M 单生成一笔 MONTHLY 模拟报文。Z 单生成 ADD、CUT 两笔独立报文，追加和追减数量均为非负十进制数，按三位小数保存；不把两笔相抵为净变化。模拟中即使某一笔为零也保留两笔以验证完整回执门槛；真实零值报文策略未确认。

每笔键由源计划、版本、M/Z 和分笔类型构成，重试保持原键。模拟接收方为每个键只生成一个 DMS 自有 ID，并独立记录源计划/版本关系。只有全部预期分笔回执通过身份、时间和唯一 ID 校验后才完成。

**已核对的外部字段名只有 `PLANE_NUM = plan_id`。** sourceVersionId、operation、items、key 和回执字段均是模拟结构，不能当作正式 DMS JSON 协议。正式 M/Z 全字段映射、认证、HTTP 端点、零值处理、事务持久化与真实接收回执均未接入，也不是本次 mock 验收的完成声明。
