已有显式 DMS 配置保持优先，其账号不匹配、密钥缺失或拒权不会回退到内置测试账号。分仓确认记录入库、分仓范围授权、快照复核、幂等和未知结果保护仍保留；DMS 登录可用不表示正式 GEA 的确认入库已配置或远端暂存已成功。

## 自定义 Host 配置

GEA Host 可使用 `dms.test` / `dms.production` 覆盖共享测试默认值。测试网关地址已按接口清单补齐；管理端地址直接采用登录接口返回的 redirect，无需预填。显式配置的账号映射须使用实际部署值，只由部署管理员提供，不能由页面填写。

```json
{
  "dms": {
    "test": {
      "gatewayUrl": "http://100.100.1.147:8000/synear_test/DMS",
      "secretEnv": "GEA_DMS_TEST_SECRET",
      "users": [{ "tenantId": "GEA租户ID", "userId": "GEA用户ID", "username": "对应DMS用户名" }]
    }
  }
}
```

登录账号也可配置 `workcode`；两者同时存在时按文档优先 username。启动 Host 的进程环境提供密钥变量，不把密钥写进页面、仓库或聊天。配置用户名必须具有所需 DMS 业务权限，真实权限继续由 DMS 校验。配置该映射即显式开放该用户的分仓 DMS 动作，不会提升通用 HTML 模型工具的影响等级。

`gatewayUrl` 支持部署路径前缀，末尾拼接文档固定路径。登录结果的 `redirect` 是免登地址来源，校验 HTTP(S)、无内嵌账号密码、`/user/loginSSO` 路径和非空 token。`manageUrl` 为可选的部署来源限制，若显式配置仍校验 origin；凭据请求不跟随 HTTP 重定向。独立 DMS 传输不进入通用请求正文日志，以免记录签名、票据或令牌。

## 三个接口与边界

- `POST /auth/oauthout/ssoLogin`：Host 用 `MD5(key + time + secret)` 小写摘要和 form 内 JSON `ssoToken` 登录，`source=ai`、`menu=/corder/ordermgt`，目标为订单管理。menu随登录请求发送，页面使用接口返回的完整redirect，不复用示例票据。
- `POST /dms/order/dmsOrderHead/submitZcOrderDirect`：Host 校验订单并携带 Bearer 凭据，回执只投影订单号和预订单号。
- `GET /auth/oauthout/getOauth2Token`：Host 适配器提供 key/menu 兑换方法并有离线测试。当前页面使用 DMS 返回的 `/user/loginSSO` 跳转页，由 DMS 页面调用取参接口完成登录；GEA 不接收原始 OAuth2 map，也不预先消耗跳转票据。

Workbench 通过当前页面 owner 的专用 `branch-dms` 操作调用可选 grant；只有非 mock 的 `inventory-fc` 适配器提供该 grant。Host 重新核分仓资源启用、GEA 登录和环境用户映射，所有调用绑定页面及身份取消信号。其他页面没有这个能力；通用 HTML action/模型工具仍保留原只读限制。

当前主数据未提供客户与分仓/收货地址/提货点的可信映射，所以页面要求显式填写编码，不用仓名或分仓编码猜提货点。此次没有新增或修改 SQL。

## 重复提交与结果未知

页面保存确认快照前先调用专用`branch-dms`的`operation: "preflight"`，参数为`warehouseCode`及待提交`order`。Host按当前可信身份校验DMS账号映射、密钥环境变量、订单结构、入库配置和分仓授权，通过时只返回`{ready: true, scope: "local-configuration"}`，不返回账号、密钥或令牌。此操作不登录、不写库、不发送订单，也不验证远程表是否存在或远程权限是否有效；这些仍由后续真实调用确认。页面与Host须配套更新。

DMS 文档没有承诺幂等。页面参考`gea-agent-fc`的确认批次逻辑，按分仓、月份、计算快照、正式计划/周期版本、消化复核结果、完整确认行（含调减到0的行）及DMS正文生成稳定意图号；Host再按环境/网关/租户/用户转换为全局预订单号。同一快照和确认内容重复提交回读原结果；同月快照或确认内容更新后可形成下一批，数量相同也不会被整个月锁为一单。

页面成功回执旁提供“重新读取，准备下一批”，重新查询并要求用户复核保留的人工调整；不会自动发单或凭每次点击随机生成新号。提交仍先重新核对快照和库中最新正式版本。旧版按月生成的意图也会被读取：同一确认内容已有成功回执则复用，旧未决批次不因算法升级被跳过。

专用`branch-dms`提交载荷须带`warehouseCode`。Host在自有`runtimeDir/dms-orders/batches`按环境/网关/租户/用户/分仓保存只追加的批次登记。原子独占创建序号文件防止并发抢占；只有前一批具有已落盘且匹配的DMS回执，才允许下一批。切换月份、修改数量或客户不能绕过该分仓的未决批次；进程重启仍保留拦截。同批次若登录尚未成功且订单尚未发出，可继续原批次；已发送但结果未知的订单仍禁止重发。该保护作用于共享同一runtimeDir的Host，不宣称跨机器的分布式锁。

Host 在 `runtimeDir/dms-orders/` 下独占创建意图文件后才发送订单，不记录登录凭据。成功回执原子写回。并发同键、进程重启、超时、异常回执或业务失败都不会自动重发；改变已占用意图号的正文也会拒绝。结果未知时须凭提示中的预订单号在 DMS 核查，不能通过修改字段或生成新号规避；当前接口文档没有查单/安全补偿接口，因此不提供自动解除未知状态入口。

Host返回回执时同时带`requestAiPreOrderCode`（页面意图号）和`aiPreOrderCode`（DMS全局预订单号）。归档按前者关联确认快照，页面展示和DMS核对使用后者；重放本地已成功回执也补齐这组关联。旧的同号回执仍可读取，关联到其他确认批次的回执拒绝保存。
