# 销售计划 · 右侧 AI 会话区原型说明 V1

> 交付对象：产品设计 / 前端实现
> 配套原型：`销售计划对话区_原型_提报版与审批版_V1.html`（自包含单文件，双击即可打开）
> 头像资产：`output/数字人头像/交付包/`（圆角方形主版 + 圆形版，各 5 个尺寸）

---

## 一、使用场景与适用目的

销售计划在业务上分**提报**与**审批**两条线，两条线的使用者、权限和数据范围都不一样，因此右侧 AI 会话区需要**两个方案**，它们共用同一套组件与交互，只切换文案与可用动作。

| 方案 | 使用场景 | 适用目的 |
| --- | --- | --- |
| **A · 提报版** | 客户，以及实际代行提报的 KA／行销综合／业务员，在提报界面右侧 | 在动手填表之前先知道「这份计划合理不合理、该改哪些」；改完能拿到累计台账；最后自己确认提交 |
| **B · 审批版** | 城市经理（区域计划审批）、省区总、大区总、品类计划各节点审核人，在审批工作台右侧 | 降低判断门槛：先给「能不能直接同意」的结论，再给卡点与处理动作，让各节点亲自参与审批而不是背书 |

---

## 二、页面结构（两版一致，五段）

按交互规范实现，自上而下固定五段，首页与会话中共用同一头部。

| 段 | 位置 | 规格 |
| --- | --- | --- |
| ① 头像与名称 | 头部常驻 + 首页形象位 | 头部圆形 30px；首页圆角方形 72px；每条 AI 回复左侧圆形 26px |
| ② 简介区 | 首页，名称下方 | 一句话说清"能帮我做什么"和"边界在哪"，用卡片承载，最多两行 |
| ③ 固定功能区 | 简介下方 | 4 项，图标 + 标题 + 一行说明，可点击直接使用 |
| ④ 推荐问题区 | 固定功能区下方 | 4 条，胶囊按钮，点击后填入输入框 |
| ⑤ 指令输入区 | 底部常驻 | 「＋」更多操作 / 输入框 / 发送键；下方居中一行"AI 生成内容请判断后使用" |

**首页与会话中的切换**：首页区块是独立于消息流的区块，用户发出第一条消息后自动收起，把空间让给消息列表；头部与头像位常驻，回复内容为空或加载中也保留头像位。

## 三、方案 A · 提报版文案（可复制）

**名称**：销售计划助手

**简介区**：
> 我可以帮你核对本月计划的合理性与风险，解释每个商品是怎么算出来的，并按你的意见调整草稿的数量与金额。最终提交仍然由你自己在确认入口完成。

**固定功能区**：

| # | 标题 | 一行说明 |
| --- | --- | --- |
| 1 | 看本月计划建议 | 任务头、总量建议、关键变化、风险提示 |
| 2 | 看需要重点关注的商品 | 发货概率偏低、库存或货龄偏高的商品 |
| 3 | 解释预测依据 | 公式怎么套算、用了哪些数据、哪项没取到 |
| 4 | 按工作台当前结果提交 | 只把你带到确认入口，不代替你提交 |

**推荐问题区**：
1. 这次预测能按现状走吗？
2. 哪些商品需要重点复核？
3. 为什么这个客户上调了？
4. 按建议帮我把数量调下来

**首屏行为**：打开工作台即自动播报一条"本月计划建议"，固定 5 段——任务头（月份 + 类型 + 截止日）、总量建议（建议总量与金额 + 环比 + 达成率）、关键变化（增量与减量前三个商品及原因）、风险提示、建议时间（本次打开实时计算的时刻）。卡片末尾两个入口：「按建议生成明细」（主）与「我要自己填」，并注明**采纳不等于提交**。

**会话回复的固定骨架**：结论 → 依据 → 缺口 → 下一步。以原型中"这次预测能按现状走吗"为例，第一句就是判断（可以按现状走，3 个商品各下调 10%），随后给逐商品依据（含发货概率与近六个月断月情况），缺口用一句话写在依据之后，最后给累计台账与 2–3 个下一步。

## 四、方案 B · 审批版文案（可复制）

**名称**：销售计划审批助手

**简介区**：
> 我可以按你当前节点的口径核对这张计划：先给结论，再给依据，异常项逐条给处理建议。我只做分析建议，不改变审批状态。

**固定功能区**：

| # | 标题 | 一行说明 |
| --- | --- | --- |
| 1 | 审这张单 | 结论先行：能不能直接同意，不能同意卡在哪 |
| 2 | 看异常清理清单 | 下市与预下市、非季节品、货龄超期、需复核 |
| 3 | 看双版本差异 | 最新版与上一版改了哪些客户和商品 |
| 4 | 生成审批意见 | 采纳记录留痕：谁采纳、改前改后 |

**推荐问题区**：
1. 这张单能直接同意吗？
2. 哪些客户需要退回重提？
3. 汤圆品类为什么比上一版降了？
4. 省区整体达成偏乐观吗？

**首屏行为**：**不自动播报**。审批是审核人主动发起的动作，默认只显示节点信息（当前节点 + 待我审批张数），由审核人点「审这张单」或直接提问后给结论，避免每切一张单就刷一条分析。

**会话回复的固定骨架**：结论 → 三维对比 → 卡点逐条 → 动作枚举。第一句直接给"能不能同意"（例如"建议先处理 2 项异常再同意，其余可直接推进"），卡点每条都给处理动作（清零、核实虚增、退回重提），并注明**同意与退回在审批工作台上执行**、采纳建议会留痕。明细默认不展开，提供"一键展开依据"。

**结论先行与异常驱动**：无异常时必须给出"无异常，可直接同意"的明确结论，不让审核人自己去数据里找问题；每级审批的决策路径控制在两次点击内。

## 五、两版差异一览

| 对比项 | 方案 A · 提报版 | 方案 B · 审批版 |
| --- | --- | --- |
| 使用人 | 客户 / 代报人 | 审批节点审核人 |
| 首屏 | 自动播报本月建议 | 不播报，等审核人发起 |
| 能做什么 | 可改草稿数量与金额、可展示确认摘要，**不代替最终提报** | **全程只读**，可给建议动作，不写审批状态 |
| 结论形态 | 能否按现状走 + 逐商品方向与幅度 | 能否直接同意 + 卡在哪几项 + 每项处理动作 |
| 风险基准 | 达成率 0.9–1.15 健康；货龄 60／90 天分档；库存覆盖对品类周转基准 | 达成率 0.9–1.15 合理；异常按项数分档；纠偏差额超 ±20% 建议走新计划 |
| 每轮收尾 | 2–3 个下一步，其中一项是把用户带到确认入口 | 2–3 个下一步，其中一项是走审批工作台执行 |
| 数据范围 | 当前页面这位客户 | 当前节点待审范围；省区／大区按整体校验，不拆单销售组 |

前端可实现为**同一个会话组件**，用配置项切换名称、简介、固定功能区、推荐问法与可用动作枚举，不必做两套。

## 六、全局约束（两版共同遵守）

1. **头像取用**：首页 72px 用圆角方形主版，头部 30px 与每条回复 26px 用圆形版；按 2 倍取图，不做拉伸、不加边框、不在头像上叠字；四周留白不小于 8%，最小显示尺寸 48px。
2. **数字颜色语义统一**：超计划为红、低于计划为绿；品牌红仅用于主按钮与少量强调，不与差额语义混用。
3. **术语禁用**：面向用户的回复不出现"把握度"以及高／中／低分档字样，概率一律写成"发货概率 + 百分比"并给出近六个月进货月份数与断月情况作为依据。
4. **每轮必须给 2–3 个下一步**，以独立小节承载、渲染为选项卡片，不得用正文末句代替，也不得写成正文里的方括号标签。
5. **不出现内部标识**：表名、字段名、参数、接口、错误码一律不出现在用户可见文案里，全部转成业务用语。
6. **结论先行**：第一句必须是判断，依据、缺口、限制都放在判断之后；唯一的例外是本轮不能执行时，限制本身就是结论。
7. **审批只读边界**：审批版不写审批状态、不代替审核人点同意或退回；提报版不代替客户最终提交。两版都不改动未经用户明确要求的商品。

## 八、待确认项

| # | 事项 | 影响 |
| --- | --- | --- |
| 1 | 审批版是否需要「看双版本差异」入口 | 若无版本对比场景，该项换成"看提报进度"或删除 |
| 2 | 审批版首屏是否要显示待审张数 | 与审批工作台的待办口径需一致 |
| 3 | 提报版固定功能区第 4 项措辞 | 「按工作台当前结果提交」为现行提示词口径，若产品侧另有入口命名需统一 |
| 4 | 两版是否共用一个 Agent 形象 | 现按共用设计（同一头像、两个名称）；若需区分形象需补第二套资产 |
| 5 | 审批版推荐问法是否按节点变化 | 现为通用 4 条；建议按节点给不同示例（省区总看整体、品类计划看进度） |
