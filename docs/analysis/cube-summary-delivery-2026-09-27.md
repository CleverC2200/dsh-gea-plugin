# Cube 汇总能力补齐与验收（2026-09-27）

三张现有模型已热加载新增 29 个指标；计划量、基地可用库存可按业务确认的“件”汇总。原有配置完整保留，服务健康，没有重启。**这解决了部分 Cube 能力缺口，不代表所有非权限问题已经解决，也不代表 GEA 各 Agent 已通过业务验收。**

本轮依据：用户提供 Cube 服务器访问，并确认 Hive `plannum/allnum` 与基地库存 `qtylive` 的单位均为“件”。经销商库存既有“箱”口径保持不变。没有修改业务数据、GEA 授权、管理端 Agent 配置或发行新客户端插件。

计划量直接读取各自源列，不把 `plannum + allnum` 再相加。不根据字段名猜测状态、调整量符号、金额币种。新汇总量只用于本模型查询，不通过跨模型连接展开后再相加。

计划候选粒度是客户×商品×归属基地×提货点，2026-08的62,616行样本核实唯一。尚未把它声明为全历史业务主键；新量在该粒度重复时保守返回NULL，留待业务核对，不能自动去重。`candidate_grain_count`与`row_count`可以解释这类阻断。

## 仍需处理的问题及根因边界

本次数据检查针对Cube `gea_agent` 数据源实际连接的PostgreSQL `data_service` 表；没有审计Hive上游同步任务本身。

| 问题 | 已确认事实 | 根因能确认到哪里 | 后续处理 |
|---|---|---|---|
| Hive计划月份滞后 | 本次源表最大`plane_date`为2026-08；该月只有一个`load_time`，为2026-07-23 | 不是单纯的前端月份过滤或Cube度量缺失；上游为什么未出现9月尚未定位 | 数据同事核对源任务、计划月份覆盖和更新时间；不自动把8月当9月 |
| 不能按省区给结果 | 最新月62,616行的省区和大区均为空/空白 | 分组能力已验证；当前阻断是这些源字段缺失。不能据此断定具体ETL故障 | 补齐源组织映射/同步；新`missing_province_count`暴露缺口 |
| 经销商在途量不完整 | 最新统计日2026-09-22，共60,948行；在途缺失46,978行，在仓缺失4行，金额缺失5行 | 现有SUM会忽略NULL，无法证明完整总量；不是再增加一个SUM就能解决 | 核实在途缺失含义与回填；未知不补0，旧合计仍需带质量说明 |
| 同批次不等于同一天库存 | 经销商同一统计日包含52个实际库存日期；实际日期缺失1,978行 | 统计日期与业务快照日期混用会产生时效误判 | 输出实际日期范围/覆盖；定义同步完整性标志 |
| “客户总数”口径 | 最新经销商库存只有435个有记录客户 | 去重库存客户数不是授权客户母集 | 需要客户主数据母集和受控绑定，不能从库存反推全部客户 |

| 安全库存不能盲目汇总 | 实际模型是`agents_scm_safety_stock`，包含目标月/版本/快照语义 | 尚未确认各字段可加粒度；不能复制基地库存SUM | 明确版本、目标与当前库存展开规则后另补指标 |
