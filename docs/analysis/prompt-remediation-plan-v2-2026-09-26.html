3. 最小目标结构：模型少记协议，宿主多承担确定工作

用户问题 + 所选Agent + 可选页面
  → 宿主确定身份、权限范围与已有能力事实
  → 相关规则 + 必需工具Schema + 本次有效结果
  → 模型选择实际查询/受管操作
  → 工具返回可读结果、完整来源与明确下一步
  → 核对事实后作答，未完成部分明确留下

继续使用现有能力注册、prompt-runtime、PromptEvidenceStore、专用查询和授权检查。将共用行为收拢到少数内部模块，接口尽量小；不新造Prompt语言、Agent管理平台、通用工作流引擎或全局缓存服务。

3.1 Prompt建议缩成三部分

  1. 共用工作规则：权限与身份、证据与精度、缺失/完整性、重试与交付边界。只维护一份。
  2. Agent差异：负责什么、常见任务、容易混淆的业务概念、何时需要专项规则。背景只保留会影响选择和判断的内容。
  3. 当前任务事实：日期/页面范围、当前真实工具、必要规则版本，以及本次已完成/尚缺的事实。覆盖更新，不把相同内容逐轮追加。

工具参数只从真实Schema提供。数据、检索内容和模型推断不提升为权限指令；由宿主提供的状态也不直接拼接未经验证的外部命令。

分仓Agent差异示例（结构示意，尚未替换现有Prompt）：

负责分仓库存、在途、待发与补货依据。先固定仓库、快照、单位和适用规则；独立查询不要求打开页面。区分现存与可用，库存快照不跨日相加。补货沿用经验证的V3规则；必要输入缺失保持未知，在途只扣一次。大日期与滞库可能重叠，没有交集证据不能相加。简单数量问题用正式聚合；复杂补货或货龄问题读取对应规则。交付已核实的结果，缺少哪部分明确说明；预览、导出和建议均不等于正式提交。

不为这段文字强行补“核心能力”等标题。业务仍可按十项检查清单审查有无遗漏，但模型看到的是针对任务有用的内容。

3.2 Skill仅承载确有价值的多步骤任务

保留可发现的name/description；正文通常只需要“完成什么、需要什么、关键步骤、交付什么”。稳定知识可放带版本的参考片段，不必为每条公式再建一个Skill。

  • 简单指标查询、解释已有数值和格式转换不强制读Skill。
  • 现有inventory-fc等篇幅并不大，先按实际任务提供相关完整内容，不为节省几十字增加调用。
  • 未来要新建Skill，必须同时满足：有独立触发场景、有清楚输入输出、有现有数据/工具可完成、与旧Skill职责不重叠、有行为测试。
  • sales-forecast-result-analysis、base-inventory-health-analysis仅保留为候选。首批不因附件给了名字就安装；需要时先复用/改造现有Skill，再决定是否值得拆出。
  • 库容推演、历史WAPE复盘、台账、通知、持续监控本次不默认新增。材料中这些要求保留为后续能力需求。

4. 首批技术措施：减少接口选择和错误往返

4.1 身份由宿主绑定，普通查询不让模型选consumer

复用现有preset与能力映射生成当前身份；模型list/resolve/stream、工具执行、知识检索、审计和证据使用一致的身份来源。无页面按所选Agent，默认销售仅用于真正的默认销售入口。

普通业务调用优先由宿主补入consumer；模型侧不再把所有consumer当作候选列表来猜。旧显式参数需兼容时，校验它与当前身份或已登记的合法跨域任务一致，不能直接透传任意注册consumer。

不能为了阻止试探，一刀切删除已有合法跨业务能力。明确的跨业务任务只沿预先登记、分别授权的路径运行，记录目标与范围；在当前通道拒绝之后临时轮换其他consumer的行为不算合法路由。首批不为此新增自动多Agent编排；暂不具备受控路径时，交付当前可做部分与具体缺口。

缓存按账号/租户、环境、consumer及相关权限/资源版本隔离，切换身份取消旧请求。目录缓存可帮助选择，但不代替每次执行所需的实际授权。

4.2 结果处理收拢：完整来源一次，展示按内容

在旧批次截断前保存完整结果或真实上游artifact；复用现有证据库，不新建另一套产物系统。子查询分别保留来源与状态，批次只是索引。

第一阶段统一必要字段即可：结果ID、来源/范围、时间/单位、成功或部分失败状态、数据覆盖、展示覆盖、原文是否可读、合法nextRead。不要一次铺开所有领域的巨型结果Schema。

  • 聚合的小表优先完整展示，不强迫模型逐页拼几个数字；大表选列/按行投影，不能切开JSON字符串。
  • “读完制品”与“数据完整”分开；查询本来只返回200行，就不能靠本地读完变成全量。
  • 只有确有完整来源和合法读取方式才返回全文引用。旧artifact兼容由宿主处理，不同时给模型两套互相矛盾的回读建议。
  • 正常续读不重复业务查询；现有销售直读若需精确重执行来重验权限/结果，保留并标为revalidation，不能宣称零网络读取。
  • 保留撤权、过期、跨会话/consumer、精确数值，以及已修好的用户JSON计算来源绑定；不因性能优化扩大复用权限。

4.3 知识检索先解决“一次返回太多”，再谈缓存

工具返回相关片段、出处、版本和覆盖限制，默认不带整段长文。已有适用的本地规则优先使用，不为重复证明同一规则再检索几十KB。

知识没有Cube的授权回执，不能伪造。没有可信知识ACL/版本重验或合法续读入口时，只在当前授权检索中返回有界正文；进一步读取重新走受控能力，不创建跨会话长期缓存或假的全文引用。

缓存不是本轮优化前提。优先让每次取到的内容少而够用，再评估是否需要带授权版本的缓存。

4.4 把“下一步怎么调用”交给工具返回

  • 保留兼容语义：Skill按行且1起点；证据按字符且0起点。参数说明、错误信息和nextRead给出一致的起点、上限与默认值。
  • 现有GEA排序参数继续由适配器转换；不让模型在Cube原生格式和GEA typed格式间自行切换。
  • 仅已登记别名可以规范化；不把猜错的成员名自动改到另一张表，更不因此切换授权对象。
  • 错误按参数、权限、无数据、数据质量、超时区分；不给所有错误同一条“重试”建议。
  • 对已知常见查询，在已有工具内返回经校验的可执行参数示例。只有任务范围、成员和必要时间条件已经明确才生成，不创建通用自动SQL代理。

5. 第二批行为优化：逐个试验，不先建大系统

5.1 重复探索看“有没有新信息”，不只看次数

将相同身份、资源版本和规范化参数的重复目录请求识别出来；新增条件、版本更新、分页、续读、刷新不误判成重复。

先给短摘要、当前匹配成员和合法下一步；仍无进展时终止该条探索路径，交付已有结果和具体缺口。授权问题停止对应范围，不连带清掉其它独立成功结果。

保留20/40安全上限，先不普遍扩大。对少量确有进展、但需完成合法续读的复杂任务再评估受控额度。对无进展循环多给20次，只会把失败拖长。

5.2 已有证据不靠模型自己回忆

优先复用目前的成功读取记录和证据索引，为每项保留：对应用户问题、取得了什么、哪部分仍缺、来源ID、时点/范围/有效性。先覆盖实际出现的几种查询，不开发通用任务状态机。

最终一次组织答案前提供小型事实摘要，例如：

已取得：两个期间的总体聚合。未取得：所需省区分组。后续M/Z过滤失败不撤销此前总体聚合。不得将总体结果称为省区全量。

任务完成标准仍由用户问题决定；数字存在不等于答对问题。结果引用、数值/单位和完成状态可机械核验，业务含义和原因充分性仍需真实模型测试及人工抽样，不能声称自由文本已被程序完全证明正确。

普通单值查询直接回答；复杂或高风险任务才增加结构化核对。避免为了验证一个简单答案固定多跑一轮模型。

5.3 规则复用从“短、完整、相关”试起

保留已经验证有效的去重逻辑。优先试验：把本次真正需要的少量已发布规则放在活跃上下文中，含规则版本与出处，随任务替换。

  • 已在实际模型输入里且本次不需要：不再读。
  • 已存在但模型明确再次请求：在预算内短重放相关完整规则，不无条件只回“已加载”。
  • 被压缩移除或版本改变：允许明确重载。
  • 不能根据材料中任意文字自动生成高优先级规则；只选已登记适用来源，不把检索结果提升为指令。

阈值、适用条件和例外必须一起返回，不能把“>95%且对应某指标”缩成孤立的95%。初期可人工维护少量关键片段，不先做通用规则抽取器或编译器。

5.4 通过对照决定是否保留

每次只改变一个主要因素：身份修复、结果结构、知识片段、活跃规则、结果摘要依次测试。同模型/档位、同工具Schema和数据范围记录完整请求及回执；服务端不能固定的因素单列。

如果“活跃规则/状态摘要”没有改善正确性或减少总成本，就不扩展。不要因为架构图好看而保留无收益层。

6. 数据与业务独立推进，既不拖住Bug修复，也不降低交付标准

首批保留六个Agent名称、职责和现有成员接口。业务材料作为规则来源和反例，维护文档不进入模型。

范围 现在可推进 需要另外补齐
销售 正确保留/交付已经成功的aggregate，修工具调用与筛选错误处理；消除M实际被is_split=1漏算的说明 原始DDL/旧模型来源、实际筛选契约、新measure/effective模型的编译与资源授权
基地 将零库存明确称为零库存，保持安全库存/目标/履约缺口区别；透出相关现有元数据 正式缺货聚合、供需匹配规则与计算、库容及批次数据
分仓 修大结果回读、仓库识别与规则调用；保留缺计划未知、在途只扣一次 可验证完整快照、单位、适用大日期定义及必要聚合
全链 修身份/授权处理及层级口径；不混公司与全渠道范围 各层实际授权、时点/单位/粒度对齐和互斥性证明
经销商 停止目录循环；明确授权客户与库存客户两种集合 授权客户主数据、库存/动销风险指标及可执行聚合
产销 无授权时停止对应范围，正确使用已存在的指标阈值 aps资源映射与真实生产/出货/满足率的查询能力

数据可用性缺口不能通过默认“件”、最大日期代表完整快照、row_count替代缺货量来掩盖。正确说明受阻是必要行为，但不计为用户业务任务已完成。

新增模型只按实际任务做增量变更，保留当前被调用的成员（包括row_count），不直接覆盖附件同名模型。指标元数据要真正传到当前GEA目录，而不是写进YAML就算完成。

两个新Skill、历史WAPE、自动台账/通知/监控、通用库存推演均放入后续能力清单，只有数据、工具和独立验收齐备才进入实施批次。现有专用预测计算器不扩成任意计算引擎。

7. 预算从“每段多短”改成“这次任务总共花了多少”

前轮首步system+tools约6.7k～8.5k字符，但基地规则追问累计工具正文151,731字符，经销商21次尝试仍未查询。继续压缩几百字的角色介绍，收益远小于消除长文和空转。

指标 本版用法
首轮12,000字符参考值 保留为防回退告警，不把它当业务验收通过标准
单次6,000字符参考值 作为默认投影预算；可完整保留的短规则/小表优先完整，必要例外服从总请求预算，不在字节中间硬切
当前有效模型输入 包含历史、工具Schema、工具正文、当前规则与状态；按真实上下文上限和输出预留计算。没有usage或可信token估计时明确记录未知/估算
调用次数 分成目录、规则、有效查询、续读、权限重验和重复无效调用；不能把合法续读一概当浪费
成本 以一次正确完成任务的总输入/输出、耗时和人工补救来比较；缓存命中单列，不能混成零输入
延迟 分连接、模型、工具、续读和重试；超时分类修好后再判断真正慢因

不再规定每个Prompt章节必须多少字符，也不把“输入≤窗口60%”当所有模型通用定律。预留量由模型窗口、输出需求、实际任务与并发返回决定；首批先可观测、能告警，再按样本校准。

8. 分四批实施，每批都能独立评审

批次A：修明确Bug和调用契约

范围：IQ-01、IQ-06、IQ-09。复用已有preset映射统一身份；补参数边界/nextRead/别名；保留安全超时分类。没有Cube部署依赖，不先重写Prompt或新增Skill。

交付：源码与定向测试、六Agent身份对照、失败前后真实请求证据。

出口：无页面和绑定页面身份正确；参数错误可修正且不会改授权对象；超时不再冒充用户取消。原来的身份与超时红灯复现转为通过，原本通过的Skill可见性对照继续通过。

批次B：完整来源与有界返回

范围：IQ-02、IQ-03。收拢旧新截断链，保留子查询完整来源；知识返回独立处理，不新增无依据的跨会话权限。

交付：原始结果恢复、中文/精确数值、部分失败、撤权/过期/重启回归；真实模型对小表与大表、知识正文的前后对照。

出口：模型可恢复真正原文，数据覆盖标记不丢失；单次知识不会再次默认灌入数万字符；总调用与读取成本有实测变化。

批次C：用小试验改善问答

范围：IQ-04、IQ-05及IQ-07的错误表述。先修目录循环、成功结果短摘要和相关规则重放；只改涉及的现有Agent/Skill。逐个试验，不一次换全部提示词。

交付：分仓大日期、经销商数量、销售省区汇总、基地规则、产销阈值这几类代表题的真实前后记录。

出口：工具已成功却被说成没有、规则已提供却被否认等已知错误不再出现；无进展目录循环能结束或转为有效取数。能力齐备任务必须实际完成，不能靠更多保守拒绝获得漂亮结果。

批次D：定向补数据能力，再整体验收

范围：IQ-07真实业务计算、IQ-08平台资源/筛选契约及必要模型增量。相关接口准备可与A/B/C并行，但不得越过各自授权。

交付：业务口径、模型/资源版本、独立预期、编译与查询证据、完整真实问答及兼容记录。

出口：具体指标可算且答案范围正确；仍缺数据的任务单独列未完成，不宣称全部Agent已可用。完成源码与测试后才形成发布候选；上线、本机切换、后台授权和Cube部署仍需相应明确授权。

最小触点：现有 src/host.ts / src/html-plugins.ts / 身份与路由逻辑；agent-tools.ts / prompt-evidence.ts / prompt-runtime.ts；gateway-catalog.ts / 工具Schema；现有预设与Skill。依实际差异收敛共享模块，不先创建完整新架构目录。

9. 验收重新设计：能定位原因，也能防止“拒绝得很正确”

9.1 三层反馈，按需扩大

  1. 确定性最小复现：身份、超时、截断、参数、授权与精度。先固定Bug，不用真实模型随机性掩盖实现错误。
  2. 固定数据＋真实模型：在隔离测试环境回放经脱敏、版本固定的工具数据，保留真实工具Schema，让模型自己决定调用。模拟权限只证明测试环境行为，不冒充生产授权验收。
  3. 真实接口＋真实模型：验证实际登录、授权、Cube、来源与答案。记录环境/版本/快照，数据变化和服务端负载变化单列，不把它们误当代码效果。

小批次只跑相关代表题；整合后重跑原14条及关键新增题。分仓Q01～Q14、预测F01～F13作为后续覆盖库，不要求开工就把所有组合跑完。

9.2 同时报告四类结果

指标 判断方式
能力覆盖 全部目标任务中，多少具备真实数据、权限和计算条件；平台阻断单列
可执行任务完成度 对预先认定可执行的任务，是否实际答完用户要求；不能事后把失败案例移出分母
答案正确性与证据一致性 数值/单位/版本/范围、成功与缺口描述、业务术语和原因是否正确
授权与异常行为 无越权/身份试探、无缺失补零、无虚构执行；正确停止不抵消其它任务未完成

工具结束或测试脚本退出0不能当业务通过。对可执行任务交付“暂时无法回答”算未完成；对确实无权限的任务，明确停止算边界通过，但业务目标仍受阻。

9.3 防止只背熟这14题

  • 保留首次回答、连续追问、长历史、新会话对照。
  • 为同一语义换说法、变更日期/仓库/单位、改变问题顺序；加入未用于调Prompt的保留题。
  • 高风险题重复运行，报告实际次数、成功/失败明细，不把3次通过当统计保证。
  • 小样本不用单一“95%”掩盖失败；先逐例满足关键事实和硬约束，再在足够、固定口径的样本上统计比例与耗时分布。
  • 记录模型/档位、工具Schema、Agent/Skill/规则版本、数据快照、实际请求和调用链。没有provider usage就不声称精确token降幅。

9.4 放行与回退

已知高风险错误——身份错位、越权、错误单位/版本混算、将未知补零、丢失唯一原文、虚构已执行——出现即不放行对应候选。不能承诺开放式模型从此永远不会出错，放行结论必须限于验证范围。

按小批次保留可定位提交与兼容版本；插件、业务套件、规则、Cube和授权配置分别记录。回退代码不自动撤销模型/权限变更，也不能通过删除会话或用户业务数据完成回退。

已有4项QA修复、严格授权、精确小数、受控审批、编码入口继续回归。完整测试在整合后运行，不为每个文案调整重复跑全仓。

10. 本次决策与后续边界

现在采纳： 同事材料中的业务区别、M/Z指标规则、来源与分层验收方法；现有六Agent/工具入口；已证实问题的小批次修复；成本和完成度一起评价。

不再作为硬要求： 十项固定运行时格式、每个复杂任务都新建Skill、两份大Skill立即上线、通用指标注册平台、所有结果统一截断到同一字符数、先全量重做Cube再修宿主。

仍需补齐但不拖住A/B： 正式缺货定义、部分资源授权/接口契约、历史事前预测、原始DDL与旧模型来源、单位/完整批次证明。相关能力未具备时不量化、不冒充已完成。

推荐先实施批次A，再做B；C按代表题逐个验证，数据侧D并行准备。 每一批的判断都是：问题是否减少、答案是否更可靠、完成任务的总成本是否下降，而不是文档是否更完整。

2026-09-26 · 仅修订方案 · 源码基线仍为 ee8a026

本版替代上一版方案的实施顺序、结构约束、新增Skill默认决策和验收数字。上一版材料评估、M-01～M-12冲突清单及来源证据继续有效；两份Agent与两份Skill草稿改为可选内容素材，不是待原样上线的配置。

本轮没有改代码、注册Skill、增加权限或执行生产测试。下面全部是拟实施措施；行为证据来自前轮14次真实问答及已保存的确定性复现。

3. 最小目标结构：模型少记协议，宿主多承担确定工作

用户问题 + 所选Agent + 可选页面
  → 宿主确定身份、权限范围与已有能力事实
  → 相关规则 + 必需工具Schema + 本次有效结果
  → 模型选择实际查询/受管操作
  → 工具返回可读结果、完整来源与明确下一步
  → 核对事实后作答，未完成部分明确留下

继续使用现有能力注册、prompt-runtime、PromptEvidenceStore、专用查询和授权检查。将共用行为收拢到少数内部模块，接口尽量小；不新造Prompt语言、Agent管理平台、通用工作流引擎或全局缓存服务。

3.1 Prompt建议缩成三部分

  1. 共用工作规则：权限与身份、证据与精度、缺失/完整性、重试与交付边界。只维护一份。
  2. Agent差异：负责什么、常见任务、容易混淆的业务概念、何时需要专项规则。背景只保留会影响选择和判断的内容。
  3. 当前任务事实：日期/页面范围、当前真实工具、必要规则版本，以及本次已完成/尚缺的事实。覆盖更新，不把相同内容逐轮追加。

工具参数只从真实Schema提供。数据、检索内容和模型推断不提升为权限指令；由宿主提供的状态也不直接拼接未经验证的外部命令。

分仓Agent差异示例（结构示意，尚未替换现有Prompt）：

负责分仓库存、在途、待发与补货依据。先固定仓库、快照、单位和适用规则；独立查询不要求打开页面。区分现存与可用，库存快照不跨日相加。补货沿用经验证的V3规则；必要输入缺失保持未知，在途只扣一次。大日期与滞库可能重叠，没有交集证据不能相加。简单数量问题用正式聚合；复杂补货或货龄问题读取对应规则。交付已核实的结果，缺少哪部分明确说明；预览、导出和建议均不等于正式提交。

不为这段文字强行补“核心能力”等标题。业务仍可按十项检查清单审查有无遗漏，但模型看到的是针对任务有用的内容。

3.2 Skill仅承载确有价值的多步骤任务

保留可发现的name/description；正文通常只需要“完成什么、需要什么、关键步骤、交付什么”。稳定知识可放带版本的参考片段，不必为每条公式再建一个Skill。

  • 简单指标查询、解释已有数值和格式转换不强制读Skill。
  • 现有inventory-fc等篇幅并不大，先按实际任务提供相关完整内容，不为节省几十字增加调用。
  • 未来要新建Skill，必须同时满足：有独立触发场景、有清楚输入输出、有现有数据/工具可完成、与旧Skill职责不重叠、有行为测试。
  • sales-forecast-result-analysis、base-inventory-health-analysis仅保留为候选。首批不因附件给了名字就安装；需要时先复用/改造现有Skill，再决定是否值得拆出。
  • 库容推演、历史WAPE复盘、台账、通知、持续监控本次不默认新增。材料中这些要求保留为后续能力需求。

4. 首批技术措施：减少接口选择和错误往返

4.1 身份由宿主绑定，普通查询不让模型选consumer

复用现有preset与能力映射生成当前身份；模型list/resolve/stream、工具执行、知识检索、审计和证据使用一致的身份来源。无页面按所选Agent，默认销售仅用于真正的默认销售入口。

普通业务调用优先由宿主补入consumer；模型侧不再把所有consumer当作候选列表来猜。旧显式参数需兼容时，校验它与当前身份或已登记的合法跨域任务一致，不能直接透传任意注册consumer。

不能为了阻止试探，一刀切删除已有合法跨业务能力。明确的跨业务任务只沿预先登记、分别授权的路径运行，记录目标与范围；在当前通道拒绝之后临时轮换其他consumer的行为不算合法路由。首批不为此新增自动多Agent编排；暂不具备受控路径时，交付当前可做部分与具体缺口。

缓存按账号/租户、环境、consumer及相关权限/资源版本隔离，切换身份取消旧请求。目录缓存可帮助选择，但不代替每次执行所需的实际授权。

4.2 结果处理收拢：完整来源一次，展示按内容

在旧批次截断前保存完整结果或真实上游artifact；复用现有证据库，不新建另一套产物系统。子查询分别保留来源与状态，批次只是索引。

第一阶段统一必要字段即可：结果ID、来源/范围、时间/单位、成功或部分失败状态、数据覆盖、展示覆盖、原文是否可读、合法nextRead。不要一次铺开所有领域的巨型结果Schema。

  • 聚合的小表优先完整展示，不强迫模型逐页拼几个数字；大表选列/按行投影，不能切开JSON字符串。
  • “读完制品”与“数据完整”分开；查询本来只返回200行，就不能靠本地读完变成全量。
  • 只有确有完整来源和合法读取方式才返回全文引用。旧artifact兼容由宿主处理，不同时给模型两套互相矛盾的回读建议。
  • 正常续读不重复业务查询；现有销售直读若需精确重执行来重验权限/结果，保留并标为revalidation，不能宣称零网络读取。
  • 保留撤权、过期、跨会话/consumer、精确数值，以及已修好的用户JSON计算来源绑定；不因性能优化扩大复用权限。

4.3 知识检索先解决“一次返回太多”，再谈缓存

工具返回相关片段、出处、版本和覆盖限制，默认不带整段长文。已有适用的本地规则优先使用，不为重复证明同一规则再检索几十KB。

知识没有Cube的授权回执，不能伪造。没有可信知识ACL/版本重验或合法续读入口时，只在当前授权检索中返回有界正文；进一步读取重新走受控能力，不创建跨会话长期缓存或假的全文引用。

缓存不是本轮优化前提。优先让每次取到的内容少而够用，再评估是否需要带授权版本的缓存。

4.4 把“下一步怎么调用”交给工具返回

  • 保留兼容语义：Skill按行且1起点；证据按字符且0起点。参数说明、错误信息和nextRead给出一致的起点、上限与默认值。
  • 现有GEA排序参数继续由适配器转换；不让模型在Cube原生格式和GEA typed格式间自行切换。
  • 仅已登记别名可以规范化；不把猜错的成员名自动改到另一张表，更不因此切换授权对象。
  • 错误按参数、权限、无数据、数据质量、超时区分；不给所有错误同一条“重试”建议。
  • 对已知常见查询，在已有工具内返回经校验的可执行参数示例。只有任务范围、成员和必要时间条件已经明确才生成，不创建通用自动SQL代理。

5. 第二批行为优化：逐个试验，不先建大系统

5.1 重复探索看“有没有新信息”，不只看次数

将相同身份、资源版本和规范化参数的重复目录请求识别出来；新增条件、版本更新、分页、续读、刷新不误判成重复。

先给短摘要、当前匹配成员和合法下一步；仍无进展时终止该条探索路径，交付已有结果和具体缺口。授权问题停止对应范围，不连带清掉其它独立成功结果。

保留20/40安全上限，先不普遍扩大。对少量确有进展、但需完成合法续读的复杂任务再评估受控额度。对无进展循环多给20次，只会把失败拖长。

5.2 已有证据不靠模型自己回忆

优先复用目前的成功读取记录和证据索引，为每项保留：对应用户问题、取得了什么、哪部分仍缺、来源ID、时点/范围/有效性。先覆盖实际出现的几种查询，不开发通用任务状态机。

最终一次组织答案前提供小型事实摘要，例如：

已取得：两个期间的总体聚合。未取得：所需省区分组。后续M/Z过滤失败不撤销此前总体聚合。不得将总体结果称为省区全量。

任务完成标准仍由用户问题决定；数字存在不等于答对问题。结果引用、数值/单位和完成状态可机械核验，业务含义和原因充分性仍需真实模型测试及人工抽样，不能声称自由文本已被程序完全证明正确。

普通单值查询直接回答；复杂或高风险任务才增加结构化核对。避免为了验证一个简单答案固定多跑一轮模型。

5.3 规则复用从“短、完整、相关”试起

保留已经验证有效的去重逻辑。优先试验：把本次真正需要的少量已发布规则放在活跃上下文中，含规则版本与出处，随任务替换。

  • 已在实际模型输入里且本次不需要：不再读。
  • 已存在但模型明确再次请求：在预算内短重放相关完整规则，不无条件只回“已加载”。
  • 被压缩移除或版本改变：允许明确重载。
  • 不能根据材料中任意文字自动生成高优先级规则；只选已登记适用来源，不把检索结果提升为指令。

阈值、适用条件和例外必须一起返回，不能把“>95%且对应某指标”缩成孤立的95%。初期可人工维护少量关键片段，不先做通用规则抽取器或编译器。

5.4 通过对照决定是否保留

每次只改变一个主要因素：身份修复、结果结构、知识片段、活跃规则、结果摘要依次测试。同模型/档位、同工具Schema和数据范围记录完整请求及回执；服务端不能固定的因素单列。

如果“活跃规则/状态摘要”没有改善正确性或减少总成本，就不扩展。不要因为架构图好看而保留无收益层。

6. 数据与业务独立推进，既不拖住Bug修复，也不降低交付标准

首批保留六个Agent名称、职责和现有成员接口。业务材料作为规则来源和反例，维护文档不进入模型。

范围 现在可推进 需要另外补齐
销售 正确保留/交付已经成功的aggregate，修工具调用与筛选错误处理；消除M实际被is_split=1漏算的说明 原始DDL/旧模型来源、实际筛选契约、新measure/effective模型的编译与资源授权
基地 将零库存明确称为零库存，保持安全库存/目标/履约缺口区别；透出相关现有元数据 正式缺货聚合、供需匹配规则与计算、库容及批次数据
分仓 修大结果回读、仓库识别与规则调用；保留缺计划未知、在途只扣一次 可验证完整快照、单位、适用大日期定义及必要聚合
全链 修身份/授权处理及层级口径；不混公司与全渠道范围 各层实际授权、时点/单位/粒度对齐和互斥性证明
经销商 停止目录循环；明确授权客户与库存客户两种集合 授权客户主数据、库存/动销风险指标及可执行聚合
产销 无授权时停止对应范围，正确使用已存在的指标阈值 aps资源映射与真实生产/出货/满足率的查询能力

数据可用性缺口不能通过默认“件”、最大日期代表完整快照、row_count替代缺货量来掩盖。正确说明受阻是必要行为，但不计为用户业务任务已完成。

新增模型只按实际任务做增量变更，保留当前被调用的成员（包括row_count），不直接覆盖附件同名模型。指标元数据要真正传到当前GEA目录，而不是写进YAML就算完成。

两个新Skill、历史WAPE、自动台账/通知/监控、通用库存推演均放入后续能力清单，只有数据、工具和独立验收齐备才进入实施批次。现有专用预测计算器不扩成任意计算引擎。

7. 预算从“每段多短”改成“这次任务总共花了多少”

前轮首步system+tools约6.7k～8.5k字符，但基地规则追问累计工具正文151,731字符，经销商21次尝试仍未查询。继续压缩几百字的角色介绍，收益远小于消除长文和空转。

指标 本版用法
首轮12,000字符参考值 保留为防回退告警，不把它当业务验收通过标准
单次6,000字符参考值 作为默认投影预算；可完整保留的短规则/小表优先完整，必要例外服从总请求预算，不在字节中间硬切
当前有效模型输入 包含历史、工具Schema、工具正文、当前规则与状态；按真实上下文上限和输出预留计算。没有usage或可信token估计时明确记录未知/估算
调用次数 分成目录、规则、有效查询、续读、权限重验和重复无效调用；不能把合法续读一概当浪费
成本 以一次正确完成任务的总输入/输出、耗时和人工补救来比较；缓存命中单列，不能混成零输入
延迟 分连接、模型、工具、续读和重试；超时分类修好后再判断真正慢因

不再规定每个Prompt章节必须多少字符，也不把“输入≤窗口60%”当所有模型通用定律。预留量由模型窗口、输出需求、实际任务与并发返回决定；首批先可观测、能告警，再按样本校准。

8. 分四批实施，每批都能独立评审

批次A：修明确Bug和调用契约

范围：IQ-01、IQ-06、IQ-09。复用已有preset映射统一身份；补参数边界/nextRead/别名；保留安全超时分类。没有Cube部署依赖，不先重写Prompt或新增Skill。

交付：源码与定向测试、六Agent身份对照、失败前后真实请求证据。

出口：无页面和绑定页面身份正确；参数错误可修正且不会改授权对象；超时不再冒充用户取消。原来的身份与超时红灯复现转为通过，原本通过的Skill可见性对照继续通过。

批次B：完整来源与有界返回

范围：IQ-02、IQ-03。收拢旧新截断链，保留子查询完整来源；知识返回独立处理，不新增无依据的跨会话权限。

交付：原始结果恢复、中文/精确数值、部分失败、撤权/过期/重启回归；真实模型对小表与大表、知识正文的前后对照。

出口：模型可恢复真正原文，数据覆盖标记不丢失；单次知识不会再次默认灌入数万字符；总调用与读取成本有实测变化。

批次C：用小试验改善问答

范围：IQ-04、IQ-05及IQ-07的错误表述。先修目录循环、成功结果短摘要和相关规则重放；只改涉及的现有Agent/Skill。逐个试验，不一次换全部提示词。

交付：分仓大日期、经销商数量、销售省区汇总、基地规则、产销阈值这几类代表题的真实前后记录。

出口：工具已成功却被说成没有、规则已提供却被否认等已知错误不再出现；无进展目录循环能结束或转为有效取数。能力齐备任务必须实际完成，不能靠更多保守拒绝获得漂亮结果。

批次D：定向补数据能力，再整体验收

范围：IQ-07真实业务计算、IQ-08平台资源/筛选契约及必要模型增量。相关接口准备可与A/B/C并行，但不得越过各自授权。

交付：业务口径、模型/资源版本、独立预期、编译与查询证据、完整真实问答及兼容记录。

出口：具体指标可算且答案范围正确；仍缺数据的任务单独列未完成，不宣称全部Agent已可用。完成源码与测试后才形成发布候选；上线、本机切换、后台授权和Cube部署仍需相应明确授权。

最小触点：现有 src/host.ts / src/html-plugins.ts / 身份与路由逻辑；agent-tools.ts / prompt-evidence.ts / prompt-runtime.ts；gateway-catalog.ts / 工具Schema；现有预设与Skill。依实际差异收敛共享模块，不先创建完整新架构目录。

9. 验收重新设计：能定位原因，也能防止“拒绝得很正确”

9.1 三层反馈，按需扩大

  1. 确定性最小复现：身份、超时、截断、参数、授权与精度。先固定Bug，不用真实模型随机性掩盖实现错误。
  2. 固定数据＋真实模型：在隔离测试环境回放经脱敏、版本固定的工具数据，保留真实工具Schema，让模型自己决定调用。模拟权限只证明测试环境行为，不冒充生产授权验收。
  3. 真实接口＋真实模型：验证实际登录、授权、Cube、来源与答案。记录环境/版本/快照，数据变化和服务端负载变化单列，不把它们误当代码效果。

小批次只跑相关代表题；整合后重跑原14条及关键新增题。分仓Q01～Q14、预测F01～F13作为后续覆盖库，不要求开工就把所有组合跑完。

9.2 同时报告四类结果

指标 判断方式
能力覆盖 全部目标任务中，多少具备真实数据、权限和计算条件；平台阻断单列
可执行任务完成度 对预先认定可执行的任务，是否实际答完用户要求；不能事后把失败案例移出分母
答案正确性与证据一致性 数值/单位/版本/范围、成功与缺口描述、业务术语和原因是否正确
授权与异常行为 无越权/身份试探、无缺失补零、无虚构执行；正确停止不抵消其它任务未完成

工具结束或测试脚本退出0不能当业务通过。对可执行任务交付“暂时无法回答”算未完成；对确实无权限的任务，明确停止算边界通过，但业务目标仍受阻。

9.3 防止只背熟这14题

  • 保留首次回答、连续追问、长历史、新会话对照。
  • 为同一语义换说法、变更日期/仓库/单位、改变问题顺序；加入未用于调Prompt的保留题。
  • 高风险题重复运行，报告实际次数、成功/失败明细，不把3次通过当统计保证。
  • 小样本不用单一“95%”掩盖失败；先逐例满足关键事实和硬约束，再在足够、固定口径的样本上统计比例与耗时分布。
  • 记录模型/档位、工具Schema、Agent/Skill/规则版本、数据快照、实际请求和调用链。没有provider usage就不声称精确token降幅。

9.4 放行与回退

已知高风险错误——身份错位、越权、错误单位/版本混算、将未知补零、丢失唯一原文、虚构已执行——出现即不放行对应候选。不能承诺开放式模型从此永远不会出错，放行结论必须限于验证范围。

按小批次保留可定位提交与兼容版本；插件、业务套件、规则、Cube和授权配置分别记录。回退代码不自动撤销模型/权限变更，也不能通过删除会话或用户业务数据完成回退。

已有4项QA修复、严格授权、精确小数、受控审批、编码入口继续回归。完整测试在整合后运行，不为每个文案调整重复跑全仓。

10. 本次决策与后续边界

现在采纳： 同事材料中的业务区别、M/Z指标规则、来源与分层验收方法；现有六Agent/工具入口；已证实问题的小批次修复；成本和完成度一起评价。

不再作为硬要求： 十项固定运行时格式、每个复杂任务都新建Skill、两份大Skill立即上线、通用指标注册平台、所有结果统一截断到同一字符数、先全量重做Cube再修宿主。

仍需补齐但不拖住A/B： 正式缺货定义、部分资源授权/接口契约、历史事前预测、原始DDL与旧模型来源、单位/完整批次证明。相关能力未具备时不量化、不冒充已完成。

推荐先实施批次A，再做B；C按代表题逐个验证，数据侧D并行准备。 每一批的判断都是：问题是否减少、答案是否更可靠、完成任务的总成本是否下降，而不是文档是否更完整。

正文完整内嵌，可离线阅读。未修改业务代码、原附件、权限或客户端。既有材料评估保留；上线、模型部署和本机切换不包含在本轮。
