## 已实施

1. `presets/prompt-policy.json` 统一公共规则、输出约定与六个业务 Persona；原生 Persona 配置不再重复存整篇业务规则。编码入口保留。
2. 普通业务首步只带 5–6 个核心工具；`gea_capabilities` 加载页面、知识库、销售、UI、委派或预测工具包。工具仍保留完整 Schema。模型可见性与原生执行限制同步，预设变化释放旧限制；旧会话只恢复同预设成功加载的能力。
3. `gea_skill` 加载相关正文和明确链接的参考片段。通过当前 `deriveMessages()` 判断正文是否仍在上下文；按名称、路径、版本和片段范围去重，压缩后可重载。
4. 五个库存/产销 Agent 的业务规则有托管源，修复旧页面工具名及无条件先读页面的规则。隐藏演示模块不进入业务启动目录。
5. 大结果在记录边界投影，完整原文和校验摘要保存在独立目录；系统只带短证据索引。历史 `availableEvidence` 不再复制进另一查询，避免混用授权范围。
6. MCP 证据绑定实际查询所用的授权快照与执行 token；回读重新核验当前用户、会话和资源版本。无有效授权凭证或空授权不产生可回读缓存。直接销售证据无资源版本接口，回读时按当前权限重新核对原查询；临时页面证据仅在原轮次使用。
7. 证据元数据可恢复，正文 hash 防止文件错配；权限撤销后不能继续读旧数据。网关会话过期由查询与回读共用分类、失效及停手机制，同轮不重建，下一用户轮再验证。
8. 普通轮次 20 次工具调用，复杂任务可扩至 40 次；每个新轮次恢复普通额度，同步预留防并发超额，模型步骤也有上限。到上限交付已有结果和未完成项，不伪报完成。
9. `gea_forecast_compute` 提供窄计算入口：不启 Shell、不联网、不写业务系统；数量使用十进制字符串，40 位有效计算精度，保留缺失、新品、节令和逐行阻断分支。拒绝已失真的大整数 number。
10. GenUI 不再全局强制出组件；业务 UI 工具禁止自动合计、无业务语义的 delta/正负默认着色。直接输出围栏仍受当前系统 UI 契约约束，没有改第三方渲染器。
11. 当前日期、时区、页面绑定作为短事实；易读金额、明确月份/组织层级、单位未知与局部缺口规则保留。欢迎文案、预设简介、快照任务提示与动作边界同步。
12. 模型流可接收真实 usage（缓存输入不重复计数）；未提供则保持未知。窗口容量仅采用服务端明确提供的值，字符统计不冒充真实 token。
13. 业务套件同步精简对话、角色、基线、范围和复核 Skill；自动分析 10 客户限制、建议卡标记、原字典/公式和 Python 计算器保留。旧阈值另列来源与适用性参考，未被冒充为已批准全局规则。
