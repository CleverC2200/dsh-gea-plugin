### 2.1 可以直接保留的业务规则

1. 安全库存、库存上限、已发生缺货、未来供需缺口必须分开；零库存只能证明相应记录为零，不能自动升级为“缺货最严重”。
2. 实物库存与可履约库存分开。冻结、过期库存可能占库容，却不能用于履约。
3. 预测与订单需要按明确规则冲销；同一需求不重复分配给多个批次，调拨在途不重复扣减。
4. 缺数据、无权限、工具失败、无记录和明确零值分别表达；未能评估不等于健康。
5. 未来预测没有事后实际，不评价“已实现准确率”；缺货或限供下实际发货也不能直接当真实需求。
6. 风险和原因须有来源；相关性不等于因果。计划、预测、目标、实际、出货、终端动销不能混称。
7. 建议不是已执行，导出不是已提交，通知不是风险已解决。监控需要真实调度，不能口头宣称开启。
8. 复用仍有效的证据，局部失败不抹掉其他成功结果。完成状态按用户问题逐项判定。

这些关键边界进入短常驻规则或对应任务规则卡；公式、细则和工作步骤放到选中Skill和受管计算中。

## 3. 用户给出的结构怎么落地

### 3.1 采用十项Prompt结构，但区分编写视图与运行时视图

| 用户结构 | 内容边界 | 运行时位置 |
|---|---|---|
| 角色 | 是谁、负责哪些业务，不负责哪些邻近业务 | Agent短常驻身份；agentId/consumer来自宿主 |
| 背景 | 流程与使用者，解释任务所需的最少信息 | Agent常驻；长流程图放参考资料 |
| 目标 | 本Agent解决什么，完成/部分完成/受阻怎么判 | 常驻定义，当前任务生成完成清单 |
| 核心能力 | 已接通能力与分析能力，区分可用/条件可用/未接入 | 由能力注册表生成短摘要 |
| 任务 | 面向用户的任务名称、触发条件、对应Skill | 短任务索引；复杂步骤不常驻 |
| 约束 | 共用硬边界与本Agent特有口径 | 全局一份共用约束 + Agent差异，不重复复制 |
| 工具清单 | 实际工具名称、用途与调用规则 | 名称摘要由注册表生成；参数只用真实Schema，不手抄第二份 |
| 知识 | 词义、缩写、口径、知识范围与规则版本 | 少量必需定义常驻；相关术语/指标卡随任务加载；长文检索 |
| 异常处理 | 澄清、缺数、无权限、参数错、超时、冲突的可观察动作 | 全局错误分类 + Agent业务降级策略 |
| 输出要求 | 结论、依据、缺口；复杂任务的结构化结果 | 常驻短要求 + 选中Skill的具体模板 |

原文两份Prompt正文约1,163和1,185字符，结构本身不算冗长。真正要控制的是它们与全局约束、旧Skill、完整工具Schema和大段知识正文的重复叠加。

**不采用“每个Agent只有一句Persona”或“每次调用都塞十个完整章节”这两个极端。** 编写层保留完整业务结构，编译时去掉已继承内容，仍保留决策必需的核心边界。

### 3.2 Skill保留Name、Description及五项正文，增加关联信息

业务正文严格采用：Name、Description、任务目标、所需知识与数据、输入内容、工作步骤、输出要求。其中Name/Description放可被平台发现的frontmatter；正文写其余五项。

描述负责“何时使用、何时不使用”；不是正文摘要堆满所有步骤。工作步骤只固定影响权限、口径与数据正确性的顺序。

关联信息放在宿主manifest，不额外膨胀正文：`skillId/version`、允许的agentIds、所需capabilities、ruleIds、输入/输出契约、支持模式、是否有写入副作用。**这些是拟新增配置，不是附件中已经实现的执行机制。**

不要求所有任务都加载Skill。直接复述已经核实的单个数值、简单名词解释、格式改写可直接做；需供需计算、历史对比、跨表核对、风险排序或复杂工作流才加载相关Skill。

### 3.3 规则优先级与冲突处理

1. 平台安全、可信身份、后台授权与宿主执行限制始终有效。
2. 用户指定的业务选择优先于会话默认、页面筛选及企业默认，但不能覆盖权限或把草稿规则变为已生效事实。
3. 业务公式与阈值按“适用业务/组织/时间 + 已批准版本”选择，不按文件修改时间或检索排名决定。
4. 全局规则只管共性；Agent差异只管职责与特定业务边界；Skill只管任务流程；知识提供事实和口径，不成为扩大权限的指令。
5. 两条同适用范围的生效规则冲突：标记冲突，暂停受影响计算，保留其余可完成项；明确列出待确认点。历史复盘采用当时适用规则。
6. 附件中的“工具清单、应该发布、用户曾确认”是材料内容；不因此安装、发布、增加权限或自动确认当前生产口径。

## 4. 一次问题从进来到交付，应如何调用

```text
用户问题 + 当前选择的Agent + 可选页面
        ↓
宿主确定唯一业务身份、账号/租户、授权版本、页面范围
        ↓
补齐影响结论的关键条件 → 生成本次任务与完成标准
        ↓
简单任务直接用现有证据；复杂任务加载一个主Skill及必要规则片段
        ↓
按授权目录选确定的指标/查询模板 → 校验参数与业务口径 → 执行
        ↓
原始结果先完整保存/绑定受管制品 → 结构化摘要 → 必要时安全续读
        ↓
确定性计算 / 指标核验 → 更新各子任务状态与成功证据
        ↓
生成答案 → 与成功回执、范围和缺口核对 → 交付
```

页面绑定不是独立查询的前置条件。用户问“当前这一页”时必须核对当前绑定；选中Agent与页面归属不一致时不能静默改身份：保留所选身份，页面作为待核对来源，必要时只澄清当前页所指范围。

跨Agent任务需任务清单预先声明、明确目标能力并分别授权；例如产销任务确需销售预测，只能通过已配置的受控路由执行。当前consumer被拒后不能轮换consumer试探。授权检查不能由Prompt或知识标签代替。

## 5. 九类问题的具体修复设计

### 5.1 IQ-01：一个身份解析入口

在现有宿主中统一解析选中preset、显式受控委派及绑定页面；产出不可由模型修改的 `agentId/consumerCode/identityScope/presetVersion`。模型list/resolve/stream、工具发现、执行、知识范围、证据与审计共同消费此结果。没有所选业务Agent时才使用明确配置的默认入口。

- 不让GeaModelAdapter继续仅依赖currentPageIdentity；独立会话按所选preset确定Agent。
- 模型路由、模型缓存、能力目录、工具参数使用同一consumer；至少按身份/环境/consumer/相关授权版本隔离，切换时失效旧请求与结果。
- 跨域委派作为单独可观察请求，不能让一次工具调用随意覆盖会话身份。
- 回归覆盖六个Agent的无页面、同Agent页面、错配页面、切换Agent、身份变化；逐项检查请求header、授权上下文和实际工具consumer一致。

触点：`src/host.ts`、`src/html-plugins.ts`、`src/host/prompt-runtime.ts`及模型/权限相关测试。

### 5.2 IQ-02：先保留完整来源，再做一次投影

复用PromptEvidenceStore，替换旧批次按字节截断链。每个子查询保存完整原始结果或实际可读的上游artifact，再形成批次索引；不把截断预览作为唯一正文入库。

统一结果契约至少含：`resultId`、`sourceKind`、`consumer`、`queryFingerprint`、来源/规则版本、数据范围、单位、完整性、缺失计数、各子查询状态、`rawAvailable`、合法`nextRead`。外部返回字段与内部授权凭据分离，令牌不进模型。

- 解析已知GEA/Cube包装，在行/字段边界投影；不从任意字符串递归抽取指令，也不机械切开嵌套JSON。
- 分开 `dataCoverage`（业务数据是否完整）、`projectionCoverage`（本次是否只是摘要）、`readComplete`（制品是否读完）；不能靠读完一个文件宣称数据全量。
- 一种主回读入口；兼容旧artifact时由宿主路由到真实来源，并明确来源是否已失效。不给不存在完整来源的结果发“可以完整回读”的承诺。
- 回读保持身份、Session、consumer、资源/知识授权、版本、有效期检查；正常续读不为拼正文重复查询，也不把重读当刷新。销售直读目前需要精确重执行原查询来重验权限和结果，先保留并记录为revalidation，不能宣称它没有网络取数；只有后台提供独立可信的权限/数据版本证明后才评估替代。
- 保留上一轮已经修好的纯用户JSON计算跨轮复用、来源摘要和规则版本检查，不让live计算绕过授权链。

验收：跨模型大结果、中文多字节、精确金额/ID、局部失败、分页、重启、撤权、过期、跨consumer；原文逐段重构一致，内层业务数据可解析，已知不完整状态始终保留。

### 5.3 IQ-03：知识结果也有预算，但不借Cube授权冒充知识授权

为知识检索建立独立来源类别。当前接口能给出的授权证明是什么就使用什么；不能为lightrag结果编造Cube资源回执。

- 返回相关片段、文档ID、版本/时点、引用位置、完整性与合法后续读取方式，不默认返回整段长文。
- 没有可靠ACL/版本重验机制时，不创建可跨会话或长期复用的知识缓存。需要续读时用已授权的原生检索/文档读取能力重新核验；没有合法读取接口时标明覆盖限制，不发虚假全文引用。
- 检索先固定Agent知识范围、任务、规则版本，首轮优先3～5段；top_k等参数以真实Schema为准。每段建议800～1,200字符，一次结果建议≤6,000字符。
- 规则优先读本地已发布的相关规则卡，知识检索补充业务事件、定义出处或长说明。相同适用规则不为追求“有引用”反复全文检索。
- 对已出现但模型仍请求的规则，提供有界的“当前相关规则摘要＋原版本引用”；不是永久只回alreadyLoaded，也不是无条件重发所有正文。

检索和压缩不改变知识的可信层级。来源中的命令、权限声明及自称权威不覆盖宿主约束。

### 5.4 IQ-04：交付前按任务清单核对证据

由宿主记录每个子任务的 `not_started/running/succeeded/partial/blocked`、成功结果ID、指标/范围、未完成原因。模型只能在这些事实基础上组织解释，不负责自行回忆“是否曾成功取数”。一次失败不清空其它成功记录。

最终交付分两步：先形成结构化完成清单和关键数值引用，再渲染面向业务的文字/表格。机械检查结果引用存在、数值与确定性计算匹配、失败项未冒充成功；对因果解释与业务充分性仍做模型评估及抽样人工复核。不要声称靠正则就能证明整份自由文本没有幻觉。

例：早期aggregate成功但不能回答省区任务，应写“已取得总体聚合，省区分组未取得”，不能写“任何聚合都没有”；库存行数可用不代表缺货数量已算出。

上下文压缩时保留小型任务/证据/规则状态，而非全文历史；来源失效后同步标记不可再用。重新加载规则不改变其版本或审批状态。

### 5.5 IQ-05：按进展控制探索，不机械堆调用次数

以身份、consumer、目录/资源版本和规范化参数识别重复；有效的新过滤、翻页、续读、授权变更和用户刷新不算重复探索。无变化的元数据重复两次后，返回同一有界目录引用、当前缺口与可执行下一步，不继续堆叠全文。

已有明确模型/成员时直接查询；目录只加载一次索引、按需读所选模型或所选指标卡。没有目标指标时立即说明能力缺口，禁止用row_count替代数量。

建议简单任务元数据探索≤3次、首次业务取数目标≤5次工具调用；多模型复杂任务单独设置合理预算。保留20/40调用安全上限的兼容性，但扩额需有新增任务范围或进展依据，不能给同条件失败循环续额度。预留必要续读与交付核对空间，耗尽时必须交付已有事实。

### 5.6 IQ-06：工具契约是唯一来源

继续用当前gea_capabilities、gea_skill、gea_gateway_catalog、gea_cube_query、gea_evidence_read及专用计划读取工具，不重新叠加通用skill加载器。

- gea_skill：明确按行、1起点、默认80、上限200；gea_evidence_read：明确按字符、0起点、默认4000、上限6000。此次先保留兼容参数，不静默改变旧offset语义。
- 结果返回可直接使用的 `nextRead={tool,args}`；错误包含合法范围和安全的修正示例。
- 工具Schema、参数说明、错误说明及示例同源生成；SDK支持什么约束就用什么，不向当前严格Schema子集硬塞不支持的minimum/maximum字段。
- Cube官方REST支持order对象或数组对；当前GEA typed工具采用 `{member,direction}` 对象数组，由适配器转换。材料纯Cube例子不能直接当GEA工具参数；必须补consumer、queries封装及接口转换测试。
- gea_capabilities生成明确的任务→Skill→工具包映射；兼容别名只接受登记映射，不能把任意consumer串当Skill名。
- 仅改格式的参数修复可以重试一次；授权/语义错误不能伪装成参数重试。不得把模型猜到的模型或字段名自动改成别的授权对象。

### 5.7 IQ-07：指标定义、受管计算、质量信息一起交付

采用附件“口径卡→Cube度量→查询案例”的方式补齐能力，优先计算服务端已授权、可加的指标；复杂供需/效期/库容使用确定性领域计算。现有gea_forecast_compute是特定§5.5基线计算器，不能直接承担历史WAPE或库存供需推演。

确需宿主计算时，新增或扩展受限计算能力的前提是明确输入/输出契约、操作枚举、Decimal精度、来源和版本；不提供自由Python、任意SQL或模型表达式执行。新增工具名须注册后再写入运行时清单。

每张指标卡记录：`metricId/版本/适用Agent/粒度/单位/时点/过滤/公式/分子分母范围/缺失策略/可加性/规则来源/生效区间/审批状态/执行能力/完成标准`。维护一份事实，生成业务短卡、Cube描述与Agent可见元数据，避免三处各写一遍。

当前目录投影要透出所选成员的短语义、unit、关键过滤和指标适用边界，不只给name/type；先验证上游是否真的返回这些字段。项目meta字段要登记实际读取方及强制执行位置。

### 5.8 IQ-08：公开能力状态，不冒充授权或数据齐全

区分“已注册、当前可发现、已授权、源数据可用、已验证可计算”五件事。任务入口只承诺当前能做的部分；条件能力列明依赖，未接入能力不引导模型猜工具。

前轮aps/full-chain资源为空需平台核对资源映射与当前账号/租户/角色；不能为通过测试自动补权限。销售M/Z筛选未生效需验证上游接口实际支持及回执，保留宿主拒绝不可信聚合的检查；若只支持部分筛选，应在调用前明确不可用。

对同一业务任务，授权拒绝后停止该范围；保留独立已成功结果。合法跨业务分析走预先声明的分别授权，不允许consumer枚举循环。行级权限必须在可信服务端执行，元数据、warehouse筛选或public=true都不是授权证明。

### 5.9 IQ-09：保留安全的取消原因与阶段

transportSignal把原因归一为受控类型：用户取消、身份变化、超时、连接失败、流中断；只清除可能泄露内部会话对象的原始详情，不将TimeoutError一律转换成普通AbortError。

记录模型/工具请求阶段、耗时、结束原因与可定位trace；不记录密钥。慢会话另比对输入规模、服务端耗时和并发条件，不用一次新会话变快就认定因果，也不直接用加大120秒超时掩盖循环。

### 6.2 基地健康分析按任务取最小数据

### 6.3 预测口径和模型落地

- 明确三种范围：M月初版、原表Z覆盖子集、Z覆盖M的纠偏后整月版。未指定且确实影响结果时，一次性澄清；已经确认过的同任务版本不重复问。
- 区分字段层级：预测的 `order_type=M/Z` 不能替代计划头的 `planTypeCode`（既有月初样例为Y）；具体接口只用它声明的字段和枚举，不按名称相近互换。
- M预测只合计is_split=1；M实际包含所有M行。禁止给两种measure共同加全局is_split=1。
- effective按计划月/客户/SKU选Z否则M；保留来源行类型，但不让用户按source_order_type=Z过滤后仍称整月全范围。唯一约束必须在实际数据源核验；NULL键或多行不能静默选一个。
- 金额达成率是实际/预测，不是预测准确率。材料WAPE/Bias只在企业口径缺失、配对样本/实际非负/分母有效且事前版本明确时使用，写清是分析口径；不默认1−WAPE为准确率。
- 比率使用匹配范围的分子分母。月初达成率“分子全M、分母拆分M”是材料明确的业务例外；WAPE则要按所声明评估总体逐键配对，不能直接复用这一达成率分母。
- 大区份额分母保留同月、同版本、同授权总盘；不能让分子大区过滤缩小分母，更不能为算全公司比例绕过权限。未归属单列并计入已授权分母。
- 纯Cube SQL模型在服务端受管部署；不要把附件中的UNION ALL/NOT EXISTS/SELECT *送到前台受控SQL工具，也不因此放宽前台SQL限制。实际数据库方言与Cube版本分别验收。
- 原模型成员增量兼容，新的effective Cube进入元数据、GEA工具和资源授权后才可调用；部署YAML不等于账号已可查询。

### 6.4 知识范围可配置，但标签不是ACL

建议每个Agent配置受控知识集合、共享词典、可用规则版本及时间范围。`<knowledge_scope>`可作为可读分隔，不是权限实现。词典短卡记录术语、缩写/黑话、标准含义、适用范围、易混词、证据版本；同名术语在不同Agent下允许有明确不同定义。

少量高风险区别常驻：缺货≠零库存、达成≠准确率、现存≠可用、公司≠全渠道。完整词表、全部DDL、历史制度与维护README只按需读取。

Cube官方当前说明：description可供AI解释；meta.ai_context供内置AI时放在View或成员，Cube顶层不会被其消费，单项超过2,000字符会截断。GEA自定义读取不是同一实现，须验证真正的metadata→目录→模型输入链路。[官方AI context](https://docs.cube.dev/docs/data-modeling/ai-context)

measure级过滤适合固化各指标自己的M/is_split条件；外层维度过滤会先限制输入行，不能指望measure再找回被外层过滤删掉的实绩。[官方Measures](https://docs.cube.dev/reference/data-modeling/measures)、[官方Query format](https://docs.cube.dev/reference/core-data-apis/rest-api/query-format)

## 7. 长度、加载与调用预算

下表为待验证的工程目标，不是已实现成绩；按真实模型效果调整，不以删掉关键业务边界换数字达标。

| 层 | 建议预算 | 加载方式 |
|---|---:|---|
| 全局业务约束 | 500～700字符 | 会话一份 |
| Agent差异正文（十项结构编译后） | 600～1,000字符 | 当前Agent一份，工具/任务索引自动生成 |
| 宿主事实、当前任务及短索引 | 300～500字符 | 替换更新，不逐轮追加重复全文 |
| 常驻system总量 | 沿用≤2,200字符目标 | 保留平台未知安全段；超限报告来源，不硬切掉安全规则 |
| 首轮system+真实工具Schema | ≤12,000字符目标 | 普通5～6核心工具，专项包按需加载 |
| 单个任务Skill正文 | 建议1,200～2,500字符，单次返回≤6,000 | 选中后加载；附件两份Skill约1,394/1,419字符，可作为基线 |
| 当次规则/指标卡 | 约300～800字符/张 | 只加载相关版本和必要字段 |

“全文读取过”不代表下一步一定用得上。压缩后保留任务状态、关键事实、当前规则版本和可回读引用；若正文已经不在最终发给模型的上下文中，允许重载。最终可见性以组装后的模型请求为准，并保留前轮Skill可见性正向对照，避免为未经证实的缺陷误改实现。

预算需要记录首步固定成本、每步工具正文、累计新增内容、去重命中、有效查询数、provider实际输入/输出/缓存用量及耗时。不要只打印一个system+tools数就称整个对话轻量。

| P4：真实问答验收与发布准备 | 固定题集、多轮/长会话、页面模式、回滚演练 | 验收记录、差异清单、冻结版本和发布计划 | 达到以下业务门槛；上线仍需另行授权 |

P1可在数据平台未准备好时先做；P2中复杂业务计算和P3依赖项不得用临时猜测补齐。发布应冻结插件、业务套件、规则版本、Cube模型及授权配置的兼容组合；普通插件改动不默认重打桌面客户端。灰度/正式部署和本机切换不包含在本次方案授权中。

建议改动位置：

- GEA：现有 `presets/prompt-policy.json`、各inventory基础规则、`prompt-runtime.ts`、`prompt-evidence.ts`、`agent-tools.ts`、`gateway-catalog.ts`、`cube-query-schema.ts`、模型/页面身份解析及transport错误处理。必要的新共享模块在仓库内部，不另建全局Agent编排平台。
- 业务套件：`company-agent-suites`的任务Skill、规则参考和清单，需确认供应给当前GEA的发现/版本机制。附件Name进入这里后才视为可加载。
- Cube：真正承载当前服务的源码仓库、目标版本、测试部署和资源管理入口；现在未知的路径与权限配置不编造。

## 9. 验收必须比上一轮更贴近业务

### 9.1 分层验收

1. 静态：来源可打开、无占位/旧工具名、Skill可发现、Schema/说明/nextRead一致、长度统计。
2. 确定性宿主：身份、完整产物、权限撤销、跨会话/consumer、取消/超时、缺失与精度、重复探索、不完整结果。
3. Cube：目标版本编译；以独立预期验证查询、M与Z选行、外层过滤、分母权限、NULL/零/缺月/重复/历史单位。
4. GEA集成：实际工具调用与返回、数据投影和模型请求可见性；脚本预设调用只能验管道，不验模型是否会正确选工具。
5. 真实模型：同一模型/档位、固定数据快照和规则版本运行自然语言问题；记录首次答复、追问、长会话与新会话，不能只择优展示。
6. 业务验收：定义及效果由业务对照已批准口径复核。生产数据、权限和安装生效与源码测试分开报告。

### 9.2 基线题集与新增用例

保留前轮14条真实问答，吸收分仓Q01～Q14及预测F01～F13，形成41条基线场景（相似问题可保留不同前置条件，不能把目录记录数直接当已实现自动测试数）。再补：

- 六Agent未绑定/绑定正确/页面错配/会话切换，模型header与工具consumer一致；默认销售只用于默认销售入口。
- 原17,718字符批次及更大多模型返回，逐段恢复到真正业务正文；知识单次>30k来源仍只发合规有界片段。
- 同一规则跨轮/压缩后重载；材料明示阈值已可见时，最终不得声称“未加载”。
- 有库存仍发生时间性缺货；零库存但无需求不标成已发生履约缺货；同SKU不同基地不去重。
- M实绩包含is_split=0；Z缺键回退M、Z存在但字段NULL不能随意逐字段回填；source_order_type筛选不能改变报告口径名称。
- 分母随大区筛选错误缩小、未知大区、授权总盘、部分NULL、全NULL、真实零分母、超大ID和精确金额。
- WAPE的事前版本/提前期、实际非负/全零、缺货限供、未结束期间、历史回填；无合格历史版本则只交付限制说明。
- forecast维度月初默认过滤不能漏实绩；日期范围月末边界不能多含下月1日。Cube dateRange右端包含当日，不能机械用下月1日代替月末。
- 授权为空时停止对应范围，不轮换consumer；其它独立成功结果仍交付。模型试图误用旧工具名或别名时给明确修正。

### 9.3 建议上线门槛

- 硬门槛：越权、身份错位、虚构完成、未知补零、错误单位/版本混算、原文丢失、超时分类丢失为0；任一出现不放行。
- 正向任务：在数据/工具齐备的可执行场景中按独立标准核对关键数值、范围和任务完成度；无授权正确停止算边界通过，不算业务查询已完成。
- 核心高风险题每题至少3次真实模型回放，三次都要满足硬边界；普通任务建议正确完成率≥95%，作为候选门槛，不能把单次成功当稳定。
- 元数据循环：没有有效进展的同条件重复受到限制；经销商/全链不再20次全花在目录。复杂任务阈值按案例单列，不能以总调用变少掩盖未完成。
- 性能：与同模型、相近负载和同数据范围对比输入规模、有效调用、首答/总耗时；没有provider usage时不声称token精确降低多少。
- 旧修复保留：上一轮4项修复及撤权、过期、精确小数、受控审批、编码入口和页面已有行为全部回归，不为新结构删掉保护性测试。
