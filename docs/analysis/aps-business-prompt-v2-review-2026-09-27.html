1. 值得保留的内容

  • 简单查询由主Agent直接回答，复杂任务才加载技能，方向正确。
  • 预测结果分析与产销问题诊断分开；前者不训练模型、不生成新预测，适合与现有预测建设技能区分。
  • 准确率与达成率分开，保持业务给出的单品偏差及初版/纠偏各50%算法；不擅自改成通用指标。
  • 缺纠偏版本时只展示可计算版本，不补零、不复制初版、不重分权重。
  • 原因分析要求对象关联、时间关系和机制证据，缺证据就停在已知层。这比堆通用“可能原因”有用。
  • 识别共享库存重复分配、未交订单覆盖、关联放大、正负抵消、跨日库存和未结期间等真实业务陷阱。
  • 区分附件中给出的映射、推导表达式和实际查询验证，允许完成独立可支持部分。

这些应保留。业务稿已经有大量“不能猜字段/不能把未知填零”要求，不需要再复制一轮通用禁止句。

三个容易混淆的口径

  1. 订单满足率：当前页面规则是1−缺货量/需求量，新稿是发货量/OMS原始需求量。仅在同池、同截止、同单位，且缺货量确实等于需求量减发货量时等价。若有截零、取消、替代品或未开订单差异，不能直接替换。
  2. 库存单位和字段：本任务确认“件”的是Hive plannum/allnum和基地qtylive，没有据此确认新稿inv_qty或全部预测量单位。经销商原有库存是箱。新稿的age_days/dt也不能直接套到现有基地模型的productage/snapshot_date。
  3. 来源与可用性：最近Cube上线的是三张模型的29项指标，不证明新稿所有订单、生产、预算表已成为APS可用资源。已有报告中APS业务数据和部分模型权限仍有待协调项，本轮未重新验权。

4. 两个最小反例

以下是本轮本地SQLite合成用例，用于验证表达式边界，不是真实业务数据，也不是线上Agent效果测试。

新鲜度：库存100件，库龄20天；另100件库龄未知。稿中L139表达式返回100%新鲜度，因为NULL不满足age_days>60，落入ELSE 0。实际只能确认一半库存的年龄；另一半是否大日期未知。应暴露未知数量并阻断完整比率。

准交率：A订单有一条准交、一条迟交记录，B订单准交。将原稿IF等价改写为CASE后，公式得到2/2=100%。如果企业整单定义要求全部应交商品满足，则该例应为1/2=50%。这不证明当前底表已存在此缺陷，证明执行前必须确认整单记录粒度与标志含义。

  订单 / 库存 / 生产 / 预算 / 任务问题分支

  data-mapping.md：源表、受控映射、成员、确认状态与缺口

这是建议结构，不是已创建或已注册的文件。优先保留两份共享参考资料，按指标组织小节，不先拆成十几个新技能。技能入口必须有平台支持的真实引用和读取方式；仅写“参见主Agent知识”不算可读取依赖。

知识状态建议拆成“业务口径是否确认”和“技术映射是否验证”两项。例如业务公式已确认、字段仍待映射时，可以解释公式或对用户提供数据计算，但不能声称已经查过当前经营数据。稿中“用户已确认”作为业务提供的确认声明保留，配上来源和适用版本，不扩展为当前会话新增授权。

主角色表达方向（示意，不作为已上线配置）

你负责产销协同的预测、计划、生产、库存与履约分析。根据本次问题选择查询、比较或诊断，公共证据和权限规则由宿主提供。

用户询问当前页面或页面自动简报时，只解释当前筛选下已成功加载的数据；独立期间、基地、区域等范围问题使用当前APS身份的授权能力，不要求先打开页面。

简单定义和查询直接回答；预测合理性、版本差异和历史偏差按需使用预测结果分析技能；已有异常需要追查原因时使用问题分析技能。已有足够偏差证据可直接诊断，跨技能复用同范围、同版本且仍有效的证据。

销售计划提报结果使用指定Hive计划来源；实时审批使用相应在线来源。预测准确率、达成率和订单满足率分别按对应指标定义计算，不能互相替代。公式、源映射和阈值按本题指标读取，不因物理表出现在材料中就视为可执行资源。

查询任务交付结果、范围与实质缺口；比较任务补充同口径差异；诊断任务补充主要对象、有依据的原因或具体待核查事项。缺事件证据时停在已确认层，不为完成模板编造原因。责任角色和行动只在问题需要时给出。

6. 两个技能的具体调整

预测结果分析：保留现有三种模式。将“从主Agent知识读取公式/映射”改成对应参考资料；补上计算业务键、初版与纠偏对应的实际数据截止、范围覆盖及是否存在选择性缺失。不改业务准确率算法，不把“分析现成预测”扩成“生成预测”。只有确实需追查执行事件时才转诊断。

产销问题分析：保留现有原因链和业务分支表。明确先选本题分支；已知库存不足并不自动证明某订单因缺货未发，当前库存也不能替代当时库存。把新鲜度空值保护和准交整单归并写入对应指标参考；“库存采用inv_qty”改为“本指标已核实源采用相应字段”，防止横跨所有库存表。按问题复杂度输出，机器枚举只用于结构化交付，普通答复用中文证据状态。
