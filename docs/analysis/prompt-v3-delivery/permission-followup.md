# 权限事项：仅记录，待用户与同事确认

依据：上一轮2026-09-26的真实测试；本轮不修改授权、不申请权限、不借用其它身份，也不重复跑已明确受阻的数据题。记录不是当前平台配置的重新核验。

| 事项 | 现象与consumer | 向同事确认的最小范围 | 权限具备后的验收 |
|---|---|---|---|
| 全链库存 | full-chain-inventory未取得匹配Cube读取资源，原题无法取得三层库存 | 测试账号/租户所属组织下，基地、分仓、客户只读资源的绑定及行字段范围；保留公司/渠道范围区分 | 当前consumer取得授权资源快照，按同快照分别查三层；越界行/字段仍应拒绝 |
| 产销实际数据 | 先前aps工具通道没有匹配数据资源；后一次固定pro又在模型调用前被拒绝，两层问题不能混为一谈 | aps所需生产计划/实际、需求/缺货、发货与库存指标的只读资源绑定；按当前组织和期间授权 | 先用已有可用模型，再查询业务指标；缺分母/目标仍未知 |
| 产销模型范围（可选） | aps实际模型清单含deepseek-v4-flash、deepseek-flash，不含此前销售默认的pro | 如确需pro，由同事确认模型授权；否则可保留现有flash，不必为了规则题扩大权限 | 在aps身份下选择其可用模型，header仍为aps；不借sales_forecast身份 |
| 部分筛选/字段被拒 | 基地版本/MZ相关调用曾被拒，尚不能一概判定缺权限 | 请核对被拒调用的资源、字段白名单与查询能力；区分策略拒绝、参数/语义不支持 | 相同身份与同一查询重放；新增权限不应扩展无关组织或字段 |

申请时需由用户补齐要授权的具体账号、租户、组织范围及有效期，不把“开全部权限”作为方案。

**不属于权限申请的事项**：数量字段只有dimension而没有sum measure、单位/完整快照未标注、销售聚合没有省区维度、规则或业务主键不清。这些属于数据契约/模型能力；仅开权限不能解决。Cube本地候选仍未部署。
