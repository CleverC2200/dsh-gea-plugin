## 2. 具体改动与行为边界

| 改动 | 解决的问题 | 边界 |
|---|---|---|
| 统一sessionConsumer与toolConsumer | 无页面库存问答错发sales_forecast；显式换consumer任意探查 | 业务Agent只能使用当前身份或代码登记的base/aps→sales路由；coding模式沿用既有行为。权限失败不通过切身份绕行 |
| 原文先落证据库 | 旧批次先按字节截断，后面续读也拿不到丢失正文 | 展示可短，原文可核验；上游本来没返回的部分不伪造。资源一成功一失败时仍显示部分失败 |
| 数据集唯一key与行模式 | 同名结果串来源、索引覆盖业务datasets、逐字符拆JSON成本高 | 依来源路径隔离；业务JSON列不递归解释；保留来源覆盖。availableRows只代表本次已收到行数 |
| 明确参数模式 | 模型猜datasetId、offset/rowOffset混用，静默退回原文 | 兼容datasetId；未知键、冲突别名、混合模式、无dataset传行参数均报错；继续兼容原有0起点字符读取 |
| 知识有界投影 | 十几万字符知识正文反复进入上下文 | 无可复用授权证明时只给一次性有出处的片段，不捏造全文evidenceId；最长4段、每段至多1200字符，整包至多6000字符。仅恢复截断JSON前部可完整解析对象，不声称读全 |
| 事实回执与目录复用 | 一次失败覆盖先前成功；反复问同样目录 | 回执是历史事实而非当前授权。目录先重验授权再复用，refresh可显式刷新；失败不会被误算为成功缓存 |
| 模型错误和观测 | Timeout变Abort/UNKNOWN，伪工具调用被当最终答复 | 保留MODEL_NOT_FOUND/超时等代码；已观察到的回答开头DSML工具标记会失败结束，绝不把文本执行为工具；不声称能识别所有伪调用 |
| agentPreset模型发现 | 用销售默认模型选择APS后直接失败 | 新RPC可发现APS自己的模型，但原生SDK list/resolve没有会话参数，库存选择器仍待接入；不偷偷借用销售身份或自动换模型 |

部分旧测试的consumer测试夹具已改为当前Agent自己的业务编码，用于继续测试后台授权拒绝；新增测试单独覆盖跨域拒绝。模拟模块仅返回本地静态说明，不走真实后端。旧网络接线测试从限定“直接throw networkError”调整为也认可转换后包装LlmError；真实Harness补测了错误码、伪完成拒绝和取消行为。

## 3. 怎么测、哪些数字不能混比

- **自动回归**：最终全量633项，630通过、0失败、3项既有纠偏UI用例跳过。`build:host`、`typecheck`通过；新定向测试覆盖6身份、全文复原、部分交付、来源隔离、结构续读、参数别名/错误、知识投影、模型错误和取消。两次独立源码审查最后无剩余必须修复项。
- **真实模型R1**：原14题，中间候选；暴露datasetId静默回退、APS模型范围不符、DSML伪完成和销售枚举臆测，之后修复。保留全部记录，不择优拼接。
- **真实模型R2**：原14题固定`deepseek-v4-pro`，7道新题也用pro；APS另做2题，用该身份实际支持的`deepseek-v4-flash`。共23次提问、16个会话，模型自主选工具，2路并行；只读GEA真实数据。
- **版本细节**：R2启动后补了“无dataset不能传行参数”的最后一条参数拒绝。逐条审计R2没有触发这种参数形态；最终注册工具测试与全量回归覆盖了它。不能称23题全部重跑了最后一字节相同的构建。
- **判分**：框架completed/脚本退出0只是结束，不等于业务正确。必须答完用户指定对象、范围、期间、单位和指标，且证据支持解释；正确拒绝另记边界通过，不能冒充取数完成。
- **可比性限制**：单次样本，服务负载/缓存/数据可能变动，非严谨性能基准。主要问题相同，但本轮修正了错误身份，这本身也改变上游路由。APS两次0.4秒以内拒绝不能当提速；flash结果不能和pro直接比较质量/成本。

早期两次分仓实验分别只答出部分结果、以及180秒被QA观察窗口取消，都未算成功。中途全量测试曾发现旧夹具冲突、一个接线源码断言过严；修复后重新跑全量，以上是最终结果，不隐藏中间失败。

**不能用一个平均提速率概括本轮。** 7道实际取数题仍是0/7完整完成；规则/边界题里，缺计划、全链周转、经销商范围和新会话缺计划4题达到本题要求。大日期/滞库解释、基地版本细则仍有缺口；APS固定pro被正确拒绝。因此并未证明整体业务完成率显著提高。

具体改善：全链周转从21次工具尝试降为2次，125.0秒降为13.4秒且口径正确；新会话缺计划从44.4秒降为16.1秒；销售从21次降为3次，改走聚合且不再把基地当省区，但没有完成省区汇总。

明确退步：分仓汇总上一版至少交付25仓可用库存，本轮最后因DSML拒绝而没有正式业务答复；基地规则题虽从86.0秒降到17.5秒，却丢失上次已取得的完整回退分支，不能算提效。

## 7. 新发现/尚未解决的问题及根因

| 编号 | 严重度 | 现象 | 根因与确认程度 | 下一步最小改法 |
|---|---|---|---|---|
| N01 | P1 | 分仓/经销商仍20次探索而未完成；全链无授权仍重复探索 | 已证实重复目录、不同拼写、refresh、Skill reload；当前只限制同请求的成功目录复用，未解决无进展的不同请求/失败探索。不能简单归因模型“没读到” | 给确定错误做一次可修复提示与有限重试；按实际进展提示直接执行已合法查询或明确缺口，不普遍增加调用额度 |
| N02 | P1 | 基地回退规则变短但丢失日期分支；滞库被解释成单纯库龄 | 短Skill是入口摘要，缺完整业务定义；模型把摘要当充分证据，R2没取得原先知识规则。知识预算和完整性不是一回事 | 把已核验的“适用条件+阈值/日期+例外+来源”作为少量完整规则片段按题加载，不照搬整篇知识库；为回退日期边界补异形题 |
| N03 | P1 | 缺安全目标被解释成未低于目标 | 缺字段、0、未触发条件三态在自然语言推理里仍被混淆；全局一句“不补零”不够 | 把是否可评价作为明确输出条件，缺目标保持未知；用0/空/不适用三组测试验收，而非再叠大量禁止句 |
| N04 | P1 | 三层异日库存被允许称混合时点公司库存 | 模型只抓住最新问句的时间问题，遗漏公司/渠道范围约束；同一Agent前一类题答对不保证新题保持 | 全链合计回答同时核对所有权边界与快照，不把时间对齐当充分条件；公司=基地+分仓与客户渠道明确并排 |
| N05 | P1 | 单“郑州分仓”题主结论用了郑州基地下11仓 | 名称相近时把地区/基地筛选当单仓实体；consumer正确不能替代业务对象正确 | 名称解析返回实体类型与唯一ID；有歧义先列可核实候选，不以范围更大的基地汇总领答 |
| N06 | P1 | 当前APS不能使用销售默认pro模型 | 修正身份暴露真实模型清单差异；原生SDK发现没有会话参数，执行校验有、选择入口接入不全 | 在库存选择入口接入按preset发现，显式选择该身份可用模型；不自动换模型。此次flash两题只证明该身份规则路径可用 |
| N07 | P1 | 最终答复曾变成DSML工具标记 | 已观察到模型在额度结束/无工具可用后输出工具语法文本；精确生成原因仍待提供方调查，不能把相关性当确定因果 | 本轮已拦截已知形式，后续评估提供方协议/模板与有限失败恢复；不能解析文本伪调用直接执行 |
| N08 | P1 | 基地量无法求和、全链缺资源、单位缺、销售省区聚合不可得 | 数据能力问题：qtylive等仅数值dimension、row_count非数量；已有聚合维度是基地；授权目录与业务母集不能替代数据 | 定向补quantity measure/单位/省区聚合/正式缺货定义和正确资源；按身份读回验收，不靠Prompt猜单位或换consumer |
| N09 | P2 | 小表已完整读到仍回头逐字符读旧原文 | 已证实事实回执只说明读过；模型仍不稳定使用已提供的小表/nextRead。原文可恢复解决丢数，不等于会高效用数 | 优先保留本题需要的小聚合表与实际读取范围，重读提示按问题相关性给nextRead；继续同题与变形题对照 |
| N10 | P2 | 长知识源存在内层JSON截断；单位/语义卡不齐 | 原始返回本身不完整是上游问题，投影不能恢复丢失后半段；目前元数据主要显示有限measure说明，未覆盖全部维度语义 | 上游返回可分页且可授权的知识正文；保留sourceComplete=false；按成员取相关完整语义卡，不全量灌目录 |
| N11 | P2 | 仍无法量化token和成本；多轮输入可达111k字符 | 提供方未返回usage；初始prompt预算不含全部历史成本 | 对接真实usage或标明估算器/模型版本后再设总预算；先观测，不用字符冒充token |

这些问题分为本地行为不足、业务契约不足和平台接入缺口，不能用一份更长的全局提示词同时解决。N02～N05尤其说明：仅压缩正文、写“必须遵守”并不能保证业务判断稳定。
