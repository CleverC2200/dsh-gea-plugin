# Business roles and official standard capabilities

GEA leaves Core standard and optional plugin capabilities under their existing registration, scope and user settings. A business role does not add a second general-tool allow list. The retired session browser/terminal restraint is removed; browser MCP still requires its existing explicit deployment setting, and sidebar/terminal tools retain their plugin-owned gates.

Manage composes selected business prompts with the active official `standard` declaration through `dsh-agent-manage/standard-preset`. Company presets use the fixed assistant sentence followed by the selected Agent prompt as their complete system text. Tool schemas and the Skill catalog remain available; automatic workspace instructions and runtime-context snapshots are omitted. GEA adds no common, knowledge, output, presentation, host-fact or turn-anchor prose. `PromptProfile.presetName` and `description` supply Agent catalog metadata independently of the Workbench page title. They pass through the selected business resource registration to both discovery and the official preset directory. `gea-html-inventory-aqkc` remains the stable Session preset id, with catalog name `基地库存Agent`, Consumer `base-safety-stock` and its original explicit cross-Consumer declarations.

GEA masks and execution guards enforce the selected business resource's declared GEA tools. Online sales reads, page reads and evidence reads follow the current [execution contract](execution-logic.md); repeated explicit calls do not exhaust a model-side allowance. General tools retain their official registration and permission policy. GEA preserves raw evidence and authorized rereads; its existing evidence projection still applies to GEA and the forecast calculator. Core standard supplies history compaction and tool-result pruning. GenUI owns its UI schema and rendering semantics.

The existing resource availability check still applies to the entire business Session. Consumer/cross-Consumer selection, server resource grants, identity generation, caller cancellation and business effect checks remain in the execution path. Restoring standard tools does not grant production writes or expose credentials to the model. Native direct sales reads stay restricted to their declared role.

Offline verification is the existing Manage `test:preset-integration` lane against explicit GEA/Workbench inputs. It boots the fixed actual Core Host providers, real Session/registry/tools/commands/compaction and actual GEA Business/tool hooks; only the external gateway and completion adapters are local. It executes base inventory queries, file/Todo/Plan/child behavior alongside business reads, actual child Consumer inheritance, automatic/manual compaction, missing identity, undeclared Consumer routes, withdrawn/disabled resources and identity-change cancellation. Production model/business calls, user-window adoption and package installation remain separate acceptance stages.
