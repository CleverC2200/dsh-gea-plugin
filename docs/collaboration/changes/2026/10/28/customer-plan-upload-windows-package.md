# Windows 三包交付兼容

在用户明确批准的“只修打包阻断”范围内，修复实际三包交付拒绝：Windows tar 列表使用 CRLF，原脚本仅按 LF 切分，使公开导出路径携带回车并误报缺失；Windows 不能直接 spawn 不带后缀的 npm，原调用返回 ENOENT；目录边界检查仅识别 ../，将 Windows 同级目标误判为源码内目录。仅规范化 tar 列表换行、按现有 Windows 调用约定使用 npm.cmd，并补齐反斜杠父级路径拒绝；保留原正斜杠拒绝规则，不放宽校验、包白名单、版本、依赖、权限或业务代码。

回归验证真实生产 CLI 的临时副本在 CRLF 列表下完成三包交付，同时仍拒绝缺失的公开导出。原失败构建与交付证据保留。修复必须通过 PR/CI 合入 main 后重做固定输入构建、交付及发布预检。本轮仍仅上传固定包和元数据，不推进签名频道，不改客户端或 Core。

本机系统 tar 的中文列表存在编码损失，发行执行改用已有 UTF-8 GNU tar，不修改业务源码。解包传给 tar 的文件及目录参数统一为正斜杠，避免 GNU tar 无法读取 Windows 临时目录；仍使用同一固定归档及普通解包入口。
