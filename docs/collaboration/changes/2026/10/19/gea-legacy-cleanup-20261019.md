# 公司客户端旧 GEA 处理

公司初始化原先只补装缺失插件，已有旧 GEA 会继续保留。现在仅用经过归档校验的随包 GEA 替换已启用且更低的正式版本。使用官方安装、文件锁与原子写入入口，保留其他依赖声明、启用选择和用户配置；严格 peer 检查禁止自动补装其他插件。升级失败保留原声明、锁和配置，停止后续自动重试。

旧壳目录的回收复用公司桌面已有的版本回收器，增加只读预览及 GEA 单包筛选。混合目录全部保留，即使其他包与公司插件同名，也不凭包名推断归属。当前、上一可用、待重启、固定、手动、迁移引用与状态不明的目录保留。不批量删除用户资源、凭据、会话或草稿，不卸载旧客户端。单实例检查提前到初始化之前，避免重复启动触发写入。

本轮收紧了首次候选中公司包白名单的不足。回归先复现混合目录会进入候选，再验证依赖、开发依赖、可选依赖、peer、启用清单和版本收据包含同名配套包时均保留。46 项定向回归通过；增量 lint、格式与差异检查通过。此前隔离 profile 的真实官方安装链已验证测试旧 GEA 0.0.130 替换为随包 0.0.164，同时保留自定义插件和配置。该证据不是新安装包验收。

历史 ASAR 依赖解析、旧版本引用保护、无初始化回执的既有配置保留与 GenUI 卸载选择均保留，并运行对应回归。没有删除旧测试、功能接口或历史记录。提交前主线为 89c17ecfd27d3cb94f3c7bc8876629fe1ca651c8；本次仅进行隔离 GitHub 的 PR 与源码合并，正式 GitLab、安装包、OSS、npm 和频道不在范围内。

本机发布技能已读取，团队来源新鲜度未核验，不据此执行正式发布。Windows 实机、原登录或身份异常的复现及安装后验收仍待完成，不能认定旧 GEA 就是用户原问题的根因。
