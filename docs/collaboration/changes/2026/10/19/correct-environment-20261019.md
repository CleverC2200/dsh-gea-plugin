# 环境就绪与发行输入纠正

本轮先处理两类重复错误，不执行插件发布或历史环境清理。

## 环境登记正确但运行依赖残缺

前一轮在登记的公司 Core 上遇到缺失 js-yaml 和 CLI 运行产物，又在本地运行检查时遇到缺少 GenUI/Sidebar。现在接收入口与直接 install/observe 在创建安装 Home 前，复用固定源码核验并实际加载所需 Boot、安装操作及 CLI profile 模块。显式源码用途另核声明的增强输入。

类型无法约束磁盘上的依赖是否被清理，因此采用单一运行检查实现，并以实际子进程回归验证。每次调用重新加载，不用过去成功回执跳过。四项 fixture 回归、接收及快检回归通过；真实残缺 Core 的模块加载复现被拒绝，现有完整 Core 的 reception 检查通过，缺少增强输入的 source 检查被拒绝。原残缺 Core 此后已有其他任务改动，完整入口也先因源码不干净而拒绝；本轮未修改它。

`test:environment` 进入既有 source-only 快检，本地与 CI 共用命令。没有增加环境池、常驻进程或自动修复共享 SDK 的路径。

## 当前发行版本被多处测试重复维护

前一轮 Workbench 升至 .11 时，安装检查仍固定 .10，包烟测仍把 .11 当成不兼容；随后的主线 .12 又修改相同列表。当前主线已经将安装版本改为读取选定 Workbench，本轮保留该实现，并删除包烟测与 manifest 测试中重复的当前版本列表。产物及锁必须保留 package.json 的兼容声明；历史 .10→.11、Manage .19→.20 使用固定输入验证：未声明时拒绝，显式扩展后接受，下一未声明版本仍拒绝。

此类问题在架构层消除重复状态，无需再加版本同步 lint 或类型。固定历史用例保留了行为边界，不随下一次发行改写。`test:release-contract` 接入现有 source-only 快检，CI 使用相同命令。

本地与 CI 共用的 `quality:fast --source-only` 六项全部通过；环境、接收、快检接线与发行合同合计 23 项定向回归通过，另有真实包烟测通过。主线更新后，pnpm 曾明确拒绝旧 workspace 安装状态；在本任务 checkout 执行冻结锁安装后，同一公开快检通过，没有放宽依赖校验或修复共享环境。
