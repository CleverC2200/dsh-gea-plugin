# 环境就绪与发行输入纠正

本轮先处理两类重复错误，不执行插件发布或历史环境清理。

## 环境登记正确但运行依赖残缺

前一轮在登记的公司 Core 上遇到缺失 js-yaml 和 CLI 运行产物，又在本地运行检查时遇到缺少 GenUI/Sidebar。现在接收入口与直接 install/observe 在创建安装 Home 前，复用固定源码核验并实际加载所需 Boot、安装操作及 CLI profile 模块。显式源码用途另核声明的增强输入。

类型无法约束磁盘上的依赖是否被清理，因此采用单一运行检查实现，并以实际子进程回归验证。每次调用重新加载，不用过去成功回执跳过。四项 fixture 回归、接收及快检回归通过；真实残缺 Core 的模块加载复现被拒绝，现有完整 Core 的 reception 检查通过，缺少增强输入的 source 检查被拒绝。原残缺 Core 此后已有其他任务改动，完整入口也先因源码不干净而拒绝；本轮未修改它。

`test:environment` 进入既有 source-only 快检，本地与 CI 共用命令。没有增加环境池、常驻进程或自动修复共享 SDK 的路径。
