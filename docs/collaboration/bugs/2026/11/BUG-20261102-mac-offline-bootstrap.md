# Mac 内置依赖齐全仍联网，超时失败持续阻断启动

客户端 0.2.0-rc.2.20261102.2 的安装日志显示，139 个包均已复用，但 pnpm 继续请求 npm registry 元数据，遇到连接重置后被 120 秒静默保护终止。随后 bootstrap 拒绝该 failed 回执，持续显示 GEA_COMPANY_INSTALL_INCOMPLETE / NOT_RECOVERABLE。

内置 pnpm 11.7.0 在安装之外并行验证锁文件的 minimumReleaseAge 等供应链策略，该验证路径仍会请求 registry。离线参数和已有包缓存不能阻止此请求。隔离 registry 对照中，原参数发出 402 次请求并失败；同一依赖集合使用 trust-lockfile 后请求为零、安装成功。

仅在公司 seed 的归档与依赖锁摘要已核验、没有用户额外依赖、且本次安装使用该冻结锁时传入 trust-lockfile。用户依赖仍遵循原检查；不全局关闭供应链策略。静默超时保护保持不变。

恢复只新增接受安装器明确记录的 120 秒静默终止日志，复用既有 profile 锁、进程退出核验、完整三包重装和配置备份。保留失败回执、原日志、禁用选择与历史数据。未知失败、供应链拒绝、活动安装和链接日志路径继续拒绝。

本地 24 项 bootstrap 回归与 79 项升级/输入回归通过。真实客户端 runtime 在 macOS 禁网沙箱内完成首次安装，并从原始失败日志及原 profile 配置恢复。打包门禁新增禁网首次安装与失败恢复验收，避免联网环境掩盖问题。

历史 Mac 打包只验证安装成功，未禁止网络，供应链元数据缓存也可能掩盖请求。本修复保留 a7c17a9e 的旧锁替换、失败回滚及用户依赖保护，保留 601265aa 的中断恢复保护，不删除功能或历史证据。

Mac 修复包发布及故障用户设备复测尚待完成；Windows 本轮不重新发布。包、源码及 CI 链接见对应 PR 和客户端 Release。
