# 公司完整包首次安装的离线依赖漂移

原包在未安装额外插件的全新 profile 中即可失败，日志为 `ERR_PNPM_NO_OFFLINE_TARBALL`，缺少 `fast-uri@3.1.9`。原公司三包保持 Workbench 0.1.17、Manage 0.6.3-company.23、GEA 0.0.177。

随包 store 实际缓存 3.1.8，registry metadata 同时包含 3.1.9。内置 pnpm 11.7.0 默认最低发布时间为 24 小时；3.1.9 在打包时未达到期限，稍后启动重新解析时达到期限，从而选中未缓存版本。

修复在 seed 准备后保存可迁移且带摘要的完整依赖锁，并在新的空 profile 安装时冻结复用。含用户依赖或已有锁的 profile 保留自己的依赖图；完整 seed 的准备入口增加独立 profile 的真实离线安装检查。原失败回执的保护条件保持，不能清除回执或用成功的新安装替代故障机恢复验收。

macOS 隔离验证复用了原三个归档、内置 Electron Node v24.18.1 和 pnpm 11.7.0。原包失败，修复候选离线安装 139 个依赖成功，保留 fast-uri 3.1.8；实际添加的本地自建插件及 profile 配置、锁、Agent 和会话夹具逐文件保留。28 项 bootstrap、refresh 与启动接线回归通过。

完整 DMG/EXE、Windows 实机和故障机恢复仍待验。当前本机构建容量门禁拒绝桌面打包，要求 28 GiB，观察约 20 GiB 可用。未修改正式客户端、发布包或更新频道。
