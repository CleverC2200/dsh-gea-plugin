# 插件构建被桌面安全余量误拦截

销售计划客户端更新时，已有依赖的 GEA host/client 编译因可用空间约 18.5 GiB 被拒绝。统一容量策略为所有操作保留 20 GiB，再加操作预算，导致纯插件编译也要求 21 GiB。

用户要求取消插件构建的统一门槛并提交 PR 合并。修复按插件与桌面操作选择安全余量，具体预算由 [buildPolicy](../../../../../scripts/build-admission.mjs) 维护。在途预留、输出目录互斥、重型写入串行和过期 owner 检查保持。

相关回归暴露了临时构建测试共用卷锁，以及独立包检查缺少冻结来源输入。构建、交付和版本戳测试使用各自临时锁目录；独立包检查从现有 profile 测试入口复用源码解析器，使依赖图准备必需资产。原业务与浏览器断言保持。并发构建回归 41 项、影响范围回归 104 项通过；正常构建入口在约 13.8 GiB 可用空间下执行成功。

最终改动仅保留容量规则及上述必需测试接线，排障期间新增的 reporter 扩展已从最终候选移除。原失败记录和定位回执保留在本任务私有验收证据中。该变更不涉及客户端业务、服务端、DMS 或用户数据。
