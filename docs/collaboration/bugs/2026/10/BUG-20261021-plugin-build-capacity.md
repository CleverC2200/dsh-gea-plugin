# 插件构建被桌面安全余量误拦截

销售计划客户端更新时，已有依赖的 GEA host/client 编译因可用空间约 18.5 GiB 被拒绝。统一容量策略为所有操作保留 20 GiB，再加操作预算，导致纯插件编译也要求 21 GiB。

用户明确指出插件构建不应受此门槛限制，并要求提交 PR 合并。修复按插件与桌面两类操作选择安全余量，具体预算由 [buildPolicy](../../../../../scripts/build-admission.mjs) 维护。原有在途预留、输出目录互斥、重型写入串行和过期 owner 检查保留。

容量边界反例在旧实现失败；修复后构建准入、开发任务、构建入口与三包交付共 39 项回归通过。新增测试分别核插件编译、打包、watch、依赖准备与桌面、SDK 的精确边界。该变更只影响开发构建工具，不修改客户端业务、用户数据、服务端或 DMS。
