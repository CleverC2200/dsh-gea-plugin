# 退回计划的通过错误依赖客户重提服务账号

- 现象：有审批角色、能看到退回计划，退回按钮可点，通过按钮置灰。
- 本地复现：同一账号和退回版本仅改变重提服务账号配置，通过按钮随之启用/禁用，退回始终可点。
- 根因：审批入口把状态 6–9 的通过强制转为客户重提，依赖服务凭据、租户和用户白名单；Host 另有退回态通过与责任节点限制，与已确认按角色重审的规则不符。
- 修复：审批人员在当前有效版本上按账号角色提交，单笔和批量不再生成重提版本；保留新鲜角色、版本、快照、契约检查；服务端显式支持角色契约时传递同一操作角色与快照。
- 历史来源：`be29875`、`784cfe0`、`17e9e5c`。这是业务规则的有意调整，不把当时对旧后端行为的兼容结论改写为线上已支持。
- 与 [桌面重提凭据问题](BUG-20260924-gea-desktop-resubmit.md) 根因不同；本次不删除客户重提和凭据加载能力。
- 验证：60 项相关测试、类型检查和插件构建通过；使用受控服务。源码审查与用户授权见 [提交审查](../../../../reviews/returned-plan-approval-20260928.md)。
- 待办：真实后端退回态/角色契约联调及后续发行。本次未部署后端、未执行生产审批，未发布插件或客户端。
