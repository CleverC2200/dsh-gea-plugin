## 二、改后原文（已落到公共层 V1.3）

```
   - **取数优先取聚合结果**：需要合计、均值、去重计数时，直接请求聚合结果，不要拆成多步。
   - **但聚合不是处处可得**：只有数据侧为这个对象预定义了聚合指标时才问得出；没有覆盖到的对象问不出合计，
     这时按顺序处理：① 只取回答真正用得上的少数几列；② 先把口径钉到唯一（见 2）；
     ③ 行数仍超出单次取出上限时，按数据侧给的位置逐段取全后自己汇总；
     ④ 拿不到全量时按【共二】10 的口径说明并给保守结论。**不得把一页明细当成全量去加总。**

5. ……**并行只用于查询之间**："先看有哪些可查对象与字段"与"发起查询"是两步，**不得放在同一次调用里并行**
   ——否则查询会拿着没核对过的字段名发出去，必然失败。

6. 明细取数按体量分档，**"是否取全"以数据侧明确给出的说法为准**：
   - 小结果一次取完即用；
   - 大结果先收窄（加筛选、减列、钉口径）；确实需要全量时，按数据侧给的位置**逐段读到它明确说"已到结尾"为止**。
     只要还有没读到的部分，就不得把已看到的当全量，按【共二】10 说明；
   - **不得用返回里的"总行数／是否完整／是否还有更多"判断取没取全**：实测这些字段会把请求的行数原样回显，
     看着完整、实际是截断的；
   - 触到单次上限时，先缩范围或减少列，只重试受影响的部分，不做多页循环拼装；
   - 中途因写法问题被拒时，先在内部改好再发一次（同一参数不要原样重试），**不向用户交代失败过程**。

7. **可查对象与字段清单只读一次，读到即逐字复用**：
   - 查询里的对象名与字段名必须**逐字来自这份清单**，不得凭业务词翻译、也不得凭印象书写；
   - 清单读过就记住，后续步骤直接引用，不重复读取；
   - 读清单与发查询分两步（见 5），不得并行。
```
