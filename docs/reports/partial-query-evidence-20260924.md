## 原问题与边界

## 改动

1. MCP 连续失败计数按会话＋consumerCode 隔离；新用户问题只清理本会话，换身份清理全部。到限返回 channel-stopped，不再由单模块失败设置全局停手。
2. 整轮重复读取和空转预算仍保留；真正触发全局停手时也返回 availableEvidence，停手不抹掉已取得的数据。
3. 从本轮实际 complete 聚合回执提取成功证据，而非让模型自行回忆。保留原查询、环境、时间、状态口径、取数范围、合计、基地和品类金额/占比；去重并控制在 24,000 字节内。优先保留先取得的整体范围。省略字段明确标注“摘要省略”，不解释成“未取到”。
4. 每个模型请求的系统段同步当前成功回执。原生 DSH 的 pre-step.messages 只是本步领取的消息，不是整段历史；因此在 agent/inbox/claimed 收到新用户问题时、系统提示组装前清理旧状态。原生双轮测试验证了第二轮不会把上一轮回执当作当前证据。
5. “成员未唯一匹配数据目录资源”单列为 GEA_MCP_RESOURCE_MAPPING_FAILED，保留网关关联编号。该文案不能单独证明跨模型或缺授权；明确的 RESOURCE_ALLOW_MISSING 仍按授权缺失处理。
6. 真机复测发现模型仍会算错状态归并和跨基地品类合计，因此 aggregate 增加确定性的 statusSummary、categoryTotals 及金额占比。回执直接带这些结果，不再要求模型心算；各品类可能共享计划，计划数不能跨品类相加。
