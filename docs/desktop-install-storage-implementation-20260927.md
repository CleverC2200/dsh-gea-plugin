# Windows 安装与历史占用优化：实施记录

日期：2026-09-27。用户授权“按照推荐的方案全量执行”。本轮完成实现、隔离验证和 Windows 本地候选构建；尚未达到正式发布验收。

## 已实现

| 范围 | 行为 |
| --- | --- |
| Windows 安装 | 在目标同级 `.new-UUID` 完整解压，检查成功后将旧目录移到 `.old-UUID`，再提升新目录；提升失败恢复原目录，恢复受阻保留备份。成功登记后删除本次旧备份。同路径跳过旧卸载器，异路径和安装范围迁移保留原流程。 |
| 路径保护 | 仅接受空目录或注册信息匹配且具有 GEA 主程序的已有安装，拒绝危险根目录及 reparse 路径。保留当前用户/全部用户安装兼容性。 |
| 日志与提示 | 解压、切换、登记、清理四阶段；实际工作中不提前显示 100%。7-Zip 只有退出码 0 才允许提升，失败输出单独记录；输出受 NSIS 字符串长度限制。未照搬官方完整 C++ helper/Job Object。 |
| 旧插件回收 | 正常启动确认 15 秒后开始；保留 active/previous/verified/booting、待重启、迁移引用、固定及手动版本。仅移走有合法收据的无引用 `channel-UUID`。短锁内改名，锁外删垃圾目录，失败下次重试。 |
| 存储边界 | 不清理登录、会话、工作区、个人配置及全局 pnpm 缓存。异常 staging、未知目录、链接和损坏收据保留。共享核心仅在引用清单完整且无引用时清理。 |
| 核心布局 | Windows 将固定核心闭包打入 `node_modules.asar`；原生模块、DLL、EXE、rg 等按实际需要解包并核对字节。Host 通过 Electron Node-mode 运行。旧全量插件图仍可使用独立 Node。 |
| 插件更新 | 先物化隔离图，使用原固定 DSH/pnpm 安装链，校验共享 Cordis 和固定官方包；完整核心闭包未变化才压回共享层。任何依赖/内容/布局变化保留完整图，不强行覆盖新的依赖。 |
| 下载 | 保留自定义 schema 1、同源不可变地址及最终 SHA-256。可选 blockmap v2 支持单段 Range 差分；失败回退一次全量，取消/权限/磁盘满不盲目重下。空闲 60 秒超时，正常慢下载没有固定总时长上限。 |
| 下载缓存 | 复用前重新验摘要；保留最近两条登记、最新两个旧格式包、本会话已展示及检测到占用的文件，成功下载后回收更早包。未知文件及遗留 part 不按年龄扫除。 |
| 发布者 | Windows 使用系统 Authenticode 成功结果，并比对客户端内嵌的公司公开证书 Subject；信任不来自远端清单。当前无公司证书配置证明，候选明确为 `legacy-unsigned`，不声称签名通过。 |

下载完成仍只定位安装包，不自动安装或重启。不升级 DSH 核心：继续使用 `0.1.6-alpha.1-company.1`；不改 GEA 插件业务及权限。

## 兼容与当前限制

- 共享版本收据使用 `dataSchema: "layered-v1:2"` 和 `coreDataSchema: 2`，让旧客户端按既有严格比较拒绝不支持的布局；用户选择文件仍为 schema 2，未迁移业务数据。新客户端能运行、回退旧完整图，**生成共享版本后不能直接用旧壳运行该共享版本**。
- 隔离真实 pnpm 安装中，`@smithy/node-http-handler`、`powershell-utils` 的提升位置变化，连带两个父包目录变化，因此触发完整图保护，随后真实 Host 和模拟业务登录通过。共享链本身已验证，但不能宣称实际每次插件更新均只增量存储。历史回收对两种图都生效。
- 安装目录恢复只覆盖本次安装失败；成功后已删除 `.old`，不等于新 EXE 启动失败时自动退回旧 EXE。插件版本启动失败回退是另一条独立链路。
- 历史异常 staging 可能仍占空间。没有完整进程所有权证据时保留，不承诺自动释放同事所说的全部十几个 GB。
- 下载差分通过 Node HTTP(S)，未声称继承 Electron/Windows 系统代理；失败可全量回退。没有新增跨进程断点续传。
- 候选 0.0.23 未进入任何频道，插件清单也未新增其 `compatible.desktop`；真实在线更新需在发布阶段补齐兼容清单。
