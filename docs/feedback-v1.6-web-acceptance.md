# V1.6 用户反馈与 Web 验收

本轮依据《需求预测Agent_测试迭代文档_V1.6.docx》修改销售计划审批工作台，提供真实 DSH Web 运行入口和浏览器 E2E。外部 GEA 与模型在自动测试中使用受控 HTTP 服务，真实环境尚未验收。

## 实施结果

| 编号 | 本轮改动 | 验证或边界 |
|---|---|---|
| 01 | 月初审批区保留通过、退回，移除重提 | 原重提 Host 能力保留；模拟审批验证草稿调整随确认通过提交 |
| 02 | 月初、纠偏切换与标题同排 | 窄面板横向滚动；不强行挤压文字 |
| 03 | 月计划读取所选版本 SKU 汇总；组织目标数量补齐聚合；版本②独立显示数量、金额和金额进度 | 历史目标缺失时明确提示；默认当前金额与数量进度均验证 50% |
| 04–05 | 审批进度不再用当前查看节点过滤；成功空查询与 403 权限错误分开 | 按当前登录可见组织范围计算；节点切换测试保持五个进度值一致 |
| 06 | 移除保存调整按钮，新增编辑调整草稿；防抖 1.5 秒持久化 | 暂存到当前 Web Host 的私有目录，**不是 GEA 数据库草稿接口**；按环境、租户、用户、计划、版本隔离，校验源快照；刷新可恢复；正式计划在确认审批前不写入 |
| 07 | 移除固定失败的模型占位适配，接入现有模型流；展示返回的物料描述 | 模型无配置、登录失效、限流、无结果、非法 JSON 等分别提示；生产主数据缺失仍需后端补齐 |
| 08 | 调整明细改为右侧无蒙层抽屉，仅显示有变化的 SKU；组织名称支持行内 SKU 展开 | 抽屉保留原队列上下文；草稿编辑独立，审批确认仍只读 |
| 09 | 页面数据就绪后自动准备当前页计划摘要，进入原生需求预测会话 | 当前会话页内按上下文去重；上下文变更取消旧请求；失败显示原因并提供重试；仅真实模型模式自动生成 |
| 10 | 导航文字单行、省略号；平板下业务与对话上下排列 | Chrome 1536×920、1024×768；既有回归覆盖嵌入面板 860/1200/580 和 700 窄屏 |

D6–D11 按文档推荐方向实施；其中 D7 受登录权限限制，只统计当前用户可读范围，不能宣称全公司总体进度。D10 的存储实现是当前 Web 服务草稿目录，若要求跨服务部署共享或 GEA 落库，仍需后端提供并确认接口。

## 验证

- `npm run typecheck`、`npm run build` 通过。
- 全量 `node --test --test-concurrency=4 tests/*.test.mjs scripts/gea-error.test.mjs`：129 项中 128 项首轮通过。剩余一项仍点击旧重提按钮，已更新并补跑通过。
- `tests/v16-web.test.mjs` 覆盖自动页面建议、SKU 建议、五节点进度不变、历史版本提示、抽屉、草稿持久化与刷新、伪造快照拒绝，以及点击确认通过才提交调整。
- `tests/web.test.mjs` 覆盖原登录、导航、账户、窄屏及表格列宽回归。
- `tests/resubmit-host.test.mjs` 保留服务端重提的身份、伪造输入及幂等校验。
- `git diff --check` 通过；界面静态检测未发现新增问题。

本地证据保存在 `.runtime/v16-feedback/`：回归日志、桌面和平板截图。该目录包含本地运行资料，不进入发行包。

## Web 使用

```sh
npm run build
npm start -- --config gea.config.json --runtime .runtime/v16-web --port 0
```

使用启动日志中的本机认证链接打开并扫码登录。进入真实模型模式的审批页面会自动分析当前可见页的数据；分析不是自动审批。
