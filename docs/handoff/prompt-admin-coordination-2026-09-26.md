# GEA Prompt优化：管理端改动与协调交接

日期：2026-09-26。对应已发布客户端插件：GEA 0.0.127（MR !184已合并，测试/正式频道均已更新）。本文是本轮管理端/业务协作的统一交接入口；未实施事项不是“已上线”。发布状态以本次MR与发行记录读回为准。

## 一、本次客户端包含什么

本次交付的是GEA插件，包含会话级业务身份、按需能力/Skill加载、完整证据保存与续读、知识返回预算、重复目录执行保护、错误分类、少量已核验库存规则。Electron壳、安装器与桌面更新协议未变。

普通数据读取仍走当前用户、当前consumer的受控通道；插件不会创建授权、部署Cube、修改管理端Agent配置或替用户发起审批。总体复杂取数完成率未达稳定验收，不能宣传所有库存Agent已经全面可用。

-## 面向业务人员的交付方式
-
-默认读者是不熟悉计算机和系统字段的业务同事。先用一句话说明“本次能给出的结果”和“还不能定的部分”，再按以下顺序交付：
-
-1. **本次结果**：预测哪个月、哪些客户/产品，以及可用的预测数量或“暂不能预测”。
-2. **需要关注**：只说明会影响业务判断的风险，例如“新品没有历史销售，暂不建议给固定数量”。
-3. **请确认或补充**：用业务语言列出需要谁确认什么，例如“请确认该客户本月计划和去年同期发货量”。
-4. **下一步**：说明拿到哪些资料后可以完成什么动作；没有真实执行回执时明确“本次只生成草案，未提交系统”。
-
-SKU 明细只保留业务识别、单位、建议数量、是否可直接使用和简短原因。数量、单位或范围不能相加/比较时，说清“暂不汇总”的业务原因。
-
-不要在默认答复中展示或逐项解释后台字段、原始 JSON、代码、接口名、资源 URI、哈希、时间戳、版本号、`data_mode`、`basis`、`source_ref`、`snapshot_at`、`status`、`coverage`、`planTypeCode`，也不要展示公式中间值、权重或计算过程。把它们留作本次工作核对信息即可。需要表达数据可靠性时改为自然语言，例如“根据本次提供的表格计算”“已拿到本月截至 9 月 12 日的数据”“有 3 个产品资料不全，暂未纳入建议”。
-
-只有用户明确要求“明细”“核对依据”“计算过程”“技术信息”或需要排查问题时，才附上“核对附录”；附录与业务结论分开，字段名同时写成业务含义。准确率指标只能称离线评测，不能宣称达到公司考核或真实业务验收。给出建议不表示已经提交或执行。
-
-在 GEA DSH 的对话分析中，先加载 `sinian-demand-dialogue`。只有已取得历史发货、库存/货龄、政策、节令等至少两类相互独立且同向的事实，并说明最近六个月发货连续性，才可以给出“建议上调/建议下调”；否则降为“建议核实”或“资料不足，建议人工核实”。预测金额接近目标预算是分配设计，不作为默认异常或调整依据。目标月尚未开始时，不用目标月实际发货、达成率或完成率判断计划。对话可以按用户明确指令修改本地草稿，但最终提交必须由用户点击固定入口完成；历史月份和已提交计划保持只读。
