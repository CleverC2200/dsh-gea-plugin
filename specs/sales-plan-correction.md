# 销售计划客户端审批纠偏规格草案

本轮按用户 2026-10-20 的最新澄清执行：纠偏查询、通过和退回复用月初接口，保存调整复用月初本地草稿 `salesPlanDraft`；M/Z 的单据差异由 `orderType` 表达。不修改后端或数据库，不执行 DMS。此前远端 SAVE 和专用纠偏 context 的实现假设不再作为客户端接入条件。

## Problem Statement

审批人需要在月初计划已终审后审核客户的追加或追减。目前既有工作台提供计划查询、调整及审批基础能力，但无法据此确认完整的 Z 单纠偏口径已经实现。审批人需要同时看清月初基准、实际发货进度、上节点确认结果和本节点草稿，并在保存、通过、退回及重提后追溯每个节点的决定。

## Solution

在销售计划审批中增加月初 M / 纠偏 Z 切换，沿用现有审批工作台、身份与流程配置。客户列表呈现固定月初基准与纠偏后计划覆盖目标的比例；逐 SKU 编辑有符号调整量，继承上节点决定并记录本节点决定。保存调整沿原本地草稿入口；通过、退回沿原审批动作入口。DMS 及后端状态推进由后续独立范围处理。

## User Stories

1. As an 审批人, I want 默认查看月初计划并切换纠偏计划, so that 我能区分两类单据。
2. As an 审批人, I want 切换后列表、选中记录和弹窗同步更新, so that 不会操作另一类单据的旧数据。
3. As an 审批人, I want 看到客户的月初终审数量及金额, so that 纠偏始终有固定基准。
4. As an 审批人, I want 两个 Tab 使用同一月度目标, so that 指标可比较。
5. As an 审批人, I want 查看累计发货数量和金额对应的计划进度, so that 我能判断实际执行情况。
6. As an 审批人, I want 发货进度分母不随纠偏变化, so that 调整计划不会改变原始执行比较口径。
7. As an 审批人, I want 查看上节点确认计划金额占月度目标的比例, so that 我能判断待审批纠偏后的计划覆盖程度。
8. As an 审批人, I want 仅纠偏视图叠加时间进度红线, so that 我能判断进度是否落后。
9. As an 审批人, I want 汇总金额说明含纠偏的净变化, so that 我能解释汇总差异。
10. As an 审批人, I want 无 Z 单时仍查看月初与发货数据, so that 无纠偏不会被误解为无计划。
11. As an 审批人, I want M 未终审时看到不可纠偏原因, so that 我不会发起无效审批。
12. As an 审批人, I want 按客户查看逐 SKU 基准、价格与调整, so that 我能核对具体商品。
13. As an 审批人, I want 编辑正负调整量并即时看到新数量和金额, so that 我能判断调整影响。
14. As an 审批人, I want 基准和联动金额保持只读, so that 计算遵循统一口径。
15. As an 审批人, I want 本节点草稿优先于上节点继承值, so that 再次打开可以继续自己的工作。
16. As an 审批人, I want 显式零调整被保留为决定, so that 零不会被当成尚未填写而重新继承。
17. As an 审批人, I want 负的新计划量被拦截, so that 不产生无效计划。
18. As an 审批人, I want 双零行不参与纠偏且追减至零行保留, so that 明细符合业务规则。
19. As an 审批人, I want 本地暂存后重新打开能读回本节点调整, so that 草稿有可靠记录。
20. As an 审批人, I want 暂存不调用远端保存或推进节点, so that 我能先保存再审批。
21. As an 审批人, I want 未修改直接通过也写入继承决定, so that 节点轨迹完整。
22. As an 下节点审批人, I want 继承上节点最新确认结果, so that 我能接续审批。
23. As an 审批人, I want 退回时填写原因且仅清本节点字段, so that 其他节点决定可追溯。
24. As an 提报人, I want 退回重提生成新有效版本并继承提报调整, so that 历史与重新审批分离。
25. As an 审批人, I want 已审或未到节点只读, so that 不会越权修改。
26. As an 管理者, I want 提交人与审批人账号分离, so that 职责分离规则得到执行。
27. As an 审批人, I want 审批窗口限制由服务端确认, so that 页面时间不能绕过业务规则。
28. As an 审批人, I want 旧版本或并发更新提示刷新, so that 我不会覆盖他人的新决定。
29. As an 审批人, I want 审批动作留下可读回的日志, so that 可以追溯数量与状态变化。
30. As an 审批人, I want 明确看到纠偏 AI 建议尚为占位, so that 不把占位内容当作真实建议。
31. As an 验收人员, I want 在模拟环境观察终审停在 5 及分笔回执, so that 可以验证回写完成门槛。
32. As an 验收人员, I want 失败原键重试、未知先对账且重复回执不重复入库, so that 可以验证异常恢复。
33. As an 验收人员, I want 只有追加和追减所需回执齐全才进入 10, so that 部分成功不被冒充全部完成。
34. As an 维护者, I want mock 与真实环境结果明确区分, so that 模拟验收不会被当作真实 DMS 联调完成。

第 31–34 项保留原后续模拟回写需求，本轮不执行或验收 DMS。

## Implementation Decisions

- 复用现有工作台、业务 Host、月初查询、草稿和审批路径、精确十进制处理、审批日志及重提路径。原接口提供动作能力或快照时沿既有校验，不为 Z 单增加专用能力门槛。
- M/Z 是单据类型，与 Y/XN/DC/FC/JD/TM 计划类型分开。按实际流程配置继承节点，不用四级示例覆盖现有跳级规则；本轮主验收采用标准四级链。
- 月初基准来自有效且未删除的 M 终审版本；目标两 Tab 同源；发货进度分母固定。纠偏后进度按上节点确认数量逐 SKU 乘价格后聚合，confirmed 不重复叠加调整。缺失与除零不展示为有意义百分比。
- 本节点调整默认按本节点、上游节点、提报逐级回退；明确区分缺失和数值零。客户列表的上节点确认口径不自动等同于本节点保存草稿。
- 调整输入呈现有符号数量，使用原月初编辑基准及数量联动模型生成 `adjustments.adjustQty`，不要求 `ABSOLUTE_NET` 模式或额外字段。原绝对净调整专用协议假设不再用于客户端请求。
- 保存调整复用月初 `salesPlanDraft` 本地暂存，不调用远端 SAVE，不写服务端 adj、confirmed 或推进节点；通过、退回复用原审批请求，由服务端处理字段及状态。
- 退回只清本节点，保留上下游字段与日志；重提生成新版本、继承提报调整且清节点字段。复用当前服务身份重提能力，不扩大用户权限。
- 审批操作沿月初既有身份、角色、有效版本与状态保护；原响应提供并发快照时须一致。过期、权限拒绝及冲突不能提示成功。本地草稿不授予审批权限。
- 窗口具体日期、跨级展示、汇总当前数量及金额时点、数量精度与舍入聚合、零值报文策略属于待核验契约；不得将建议 13–15 日硬编码成已确认规则。数据设计 V1.14 与实际 GEA 协议尚未核验，接口示例不等同于已部署接口。
- 正式 GEA 的字段和服务端规则按原接口核验，不以新增纠偏 context、节点默认字段或模式字符串缺失阻断原审批链。受控测试与真实服务验收分别记录。
- 发货数量来自已核对的 `agents_order_execute_isontime_mi`，按当前可见客户和月份读取 `qtyshipped`；金额来源及数量单位待用户确认，缺失金额保持未知。
- 本轮不执行 DMS 或修改后端、数据库。#23 模拟接收及原回执保留为历史，不据此把真实 GEA 计划置为 10。
- 纠偏 AI 建议使用明确占位，不直接沿用月初建议结果冒充纠偏建议；真实算法与输入契约后续处理。

## Testing Decisions

- 主验收入口建议为现有真实 DSH Web profile：浏览器操作真实页面，经实际 Host 与认证 Fetch，到受控 GEA HTTP 服务，独立读回状态、数量、版本及审批日志。公开 Host Business 加外部 HTTP 替身也是用户确认的测试入口；本轮不调用 DMS。
- 沿用月初本地草稿回读、Host 原权限与快照检查、审批及退回重提测试的装配方式，不为纠偏新建远端保存协议或重复测试页面。
- 每个任务都交付该行为的端到端验证，检查界面、实际请求和独立回读，而非只检查函数调用、按钮存在或成功提示。HTTP 成功不能代替业务状态确认。
- 对有符号数量、继承零值、精确金额等必要组合规则复用原规则测试；不重复公开入口已证明的实现细节。
- 各写切片均包括错误身份、旧版本/快照、权限拒绝、网络失败与并发冲突。重新登录和切换 Tab 不可复用旧草稿发起写入。
- 月初回归覆盖既有查询、保存、审批和重提，防止纠偏规则改变原有语义。模拟与真实 GEA 验收分别记录，本轮不验收 DMS。

## Out of Scope

- DMS 调用、模拟衔接、正式接口开发、报文定稿、认证配置、生产回写及以模拟回执完成真实计划。
- 提报端页面重做；本期仅覆盖审批退回后的既有重提链路适配。
- 真实纠偏 AI 算法、自动审批或模型自主写业务数据。
- 未核验的数据设计迁移、任意新建后端端点和生产权限变更。
- 单独重做 #23 已完成的模拟接收方，以及无证据支持的大范围重构。
