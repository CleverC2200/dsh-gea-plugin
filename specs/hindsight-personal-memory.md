## 用户行为

- 现有设置弹窗在插件管理下方增加同级“记忆与进化”，沿用布局、主题和公共 UI。生成对话记忆开关、新用户默认关闭；工作背景/表达偏好/工作习惯分类、搜索、数量、最近更新时间、来源、编辑、删除、清空。
- 生成开关仅控制自动提取和自动更新。关闭后已有记忆仍参与召回，列表和手工编辑删除仍可用。开关按完整身份在服务端持久化，A 的开关不改变 B。
- 仅对开启后当前用户新回合的原始新增输入生成，回合结束后后台处理，不阻塞对话。只处理稳定个人背景、表达偏好与工作习惯；临时任务、假设/引用、助手猜测、插件注入、工具结果、密钥验证码与附件全文不进入提取。没有候选不产生记录。不回扫旧会话。
- 保存独立短条目，术语见 [个人记忆术语](../GLOSSARY.md)。条目身份在更新中稳定，同一条目同时只有一个可用当前版本；自动更新先保存独立候选版本，确认成功且 scope 版本仍有效后才切换。失败、关闭或结果未知时保留原当前版本，被放弃候选及被替换旧版本进入持久清理。Hindsight chunks 模式避免二次拆分，元数据含分类、标题、版本、人工编辑标记和来源会话/消息/时间，正文只保存在 Hindsight。observations 派生数据不直接作为可编辑列表行。
- 新信息可更新未人工修改的已有条目；手工编辑后标记“你已编辑”，自动生成不能覆盖或另建矛盾条目。删除不禁止后续新对话重新产生类似记忆。
- 编辑为空拒绝；失败保留草稿；带版本提交，冲突提示重新加载。处理中阻止重复提交。超时未知显示结果待确认并查原操作，重试复用同一操作 ID。
- 删除单条二次确认；清空所有分类需输入“清空”，不只清当前筛选。两者均保持生成开关值，不删除聊天记录。删除清理 document、事实、向量与相关派生可用内容，并清理含正文的父子异步操作记录及已删条目的标题、来源等内容性元数据，不用可恢复 invalidate 冒充永久删除。部署在创建真实GEA个人记忆bank之前关闭Hindsight原始LLM trace，实证不再产生调试正文副本；已知本票合成bank的旧trace按精确范围清理。备份/WAL即时擦除不在完成声明；恢复需重放删除元数据。
- 关闭生成、手工编辑、删除或清空优先于在途自动任务。每用户使用持久化版本屏障，自动任务捕获版本，最终检查与当前版本切换同手工操作串行，候选远端处理不占控制操作的锁；过期任务丢弃。清空先切到新空 bank 代次，旧任务只能指向旧代次，撤销旧任务并清理旧 bank。
- 关闭确认以后不得提交旧自动任务；已提交后端的任务须核查并清理，结果未知不得报成功。删除/清空期间退出可召回范围，完成后不得被缓存/派生摘要或迟到任务恢复。

## 身份与边界

GEA Host 唯一持有业务凭据。独立个人记忆插件只用 Host-only geaMemory 能力。公司网关每次沿固定环境的 /sys/user/getUserInfo 在线校验 token，取 environment、loginTenantId ?? tenantId、稳定 userInfo.id。客户端 bank/schema/tenant/user/任意 URI 或转发路径不授予归属。完整三元组加清空代次映射稳定 Hindsight bank；不同环境/租户/用户均分离，bank逻辑隔离，共用 PostgreSQL schema。

所有 list/get/recall/generate/edit/delete/clear/operation 都重新按当前用户限定对象。Hindsight key、数据库 key 和原始 MCP/管理接口不下发。上游401映射后端故障，不误登出 GEA；只处理当前身份确证失效，迟到401不能登出新用户。

会话第一次使用个人记忆后绑定 scope，GEA 记忆守卫用现有存储保存 sidecar，不改不可变 SessionHeader。切账号取消旧等待并清缓存/草稿/旧回执；带旧身份记忆的会话禁止交给新身份模型继续，提示切回或新建。恢复、fork、压缩继承限制。Core 仍拥有历史，不声称保护同一OS用户的本地历史浏览。

## 公共接口与测试授权

用户已批准的验证入口具体化为：公司 HTTP 网关、GEA geaMemory/Host routes、独立插件的 agent/pre-step 与 session/event、真实设置 UI 操作。TDD 从这些公开入口验证用户行为，外部 GEA/Hindsight/模型可用真实本地HTTP替身，内部模块不造重复mock。测试不直接查内部DB来替代可见结果；用列表、召回与操作状态回读验证。此具体化来自已批准方案与最新明确验证指令，不另请求已授权许可。

建议公开网关以 /v1/memory 为前缀：state、settings、list/get、recall、generate、update/delete、clear、operations。精确字段由首票提交的共享合同单一维护；禁止为未实现接口伪造成功。所有回执带已验证 scope，写操作有稳定 operationId、版本与明确 completed/processing/failed/unknown 等状态。
