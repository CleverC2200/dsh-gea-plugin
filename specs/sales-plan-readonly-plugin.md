## Problem Statement

用户希望把 AionUi 中的 GEA 销售计划业务迁移到 DeepSeek Harness，并通过个人 fork 管理工作，避免为了业务页面和接口长期维护 dsh 核心源码分支。

外部插件原型已经证明：在未修改的 dsh npm 发布版上，可以加载业务页面、独立扫码登录测试 GEA、查询真实计划、把一条记录送入标准 Session，并从持久化日志读回与模型请求一致的数据。原型仍只展示第一页的少量字段，模型返回的是本地验证回执；它尚不能支持日常查看详情、版本、SKU 明细或真实 AI 分析。

本规格定义第一版可用的销售计划只读 Web 插件。它完成从业务查询到可追溯分析的流程，不将原型的传递验证等同于完整业务迁移验收。

## Solution

用户通过独立安装的 GEA 插件进入销售计划页面，明确看到当前环境和登录状态，按周期及服务端支持的条件查询计划，查看计划详情、版本和 SKU 明细，并将明确选中的数据交给真实模型分析。分析结果与输入数据保存在 dsh Session 中，重新打开后可以核对当时的数据来源、版本、时间和覆盖范围。

插件通过 dsh profile、Web 插槽、认证 Fetch、标准 Session 接口和现有 LLM capability 工作。首版面向本机单人 Web 使用，以已验证的 dsh 发布版本为兼容基线，继续保持 dsh 源码零改动。GEA 业务读操作由外部 Host 插件负责；分析流程不提供业务修改、审批或写回能力。

## User Stories

1. 作为部署者，我希望独立安装和升级 GEA 插件，以便业务迭代无需修改 dsh 源码。
2. 作为部署者，我希望明确知道插件支持的 dsh 版本和启动方式，以便复现已验收的运行环境。
3. 作为部署者，我希望通过配置选择 GEA 环境、请求超时和分页限制，以便迁移目录或环境时无需编辑业务源码。
4. 作为销售计划使用者，我希望从 dsh 侧边栏进入业务页面，以便在同一应用中完成查询与分析。
5. 作为销售计划使用者，我希望看到当前 GEA 环境和已验证的登录身份，以便确认正在访问哪套数据。
6. 作为销售计划使用者，我希望通过飞书扫码登录，以便使用自己在 GEA 中的业务权限。
7. 作为销售计划使用者，我希望二维码过期后能明确看到原因并重新获取，以便继续登录。
8. 作为销售计划使用者，我希望登录失效时停止受保护的查询并提示重新登录，以便不会把失效状态误认为没有业务数据。
9. 作为销售计划使用者，我希望切换环境后重新建立对应环境的身份，以便凭证和查询结果不会跨环境混用。
10. 作为销售计划使用者，我希望选择销售周期，以便查询正确业务期间的计划。
11. 作为销售计划使用者，我希望使用服务端支持的计划类型、状态等筛选条件，以便缩小计划范围。
12. 作为销售计划使用者，我希望翻页并看到返回总数、当前页和查询条件，以便了解列表覆盖了多少记录。
13. 作为销售计划使用者，我希望区分加载中、空列表、权限不足和服务故障，以便知道下一步该等待、调整筛选还是处理登录或权限。
14. 作为销售计划使用者，我希望看到接口提供的组织、经销商、计划类型、状态、数量、金额及更新时间，以便识别需要查看的计划。
15. 作为销售计划使用者，我希望未知状态码和缺失字段仍被明确展示，以便不会被未经确认的名称或默认值误导。
16. 作为销售计划使用者，我希望数量、金额和业务标识保留接口精度，以便页面和分析不会因数值转换而改变业务事实。
17. 作为销售计划使用者，我希望打开所选计划的详情，以便查看列表未包含的信息。
18. 作为销售计划使用者，我希望查看计划版本并明确当前选择，以便分析对应的版本数据。
19. 作为销售计划使用者，我希望查看所选版本的 SKU 明细，以便核对计划中的商品组成。
20. 作为销售计划使用者，我希望快速切换筛选、计划或版本时只显示当前选择对应的响应，以便旧请求不会覆盖新数据。
21. 作为销售计划使用者，我希望查询失败或环境变化后旧数据不能被误发送，以便分析使用的是我明确选中的有效快照。
22. 作为销售计划使用者，我希望在发起分析前看到选中的计划、版本和数据覆盖范围，以便知道哪些信息会交给模型。
23. 作为销售计划使用者，我希望模型说明计划中的数量或金额差异，并区分业务事实、计算结果和推测，以便判断分析依据。
24. 作为销售计划使用者，我希望缺少详情、SKU 或比较依据时模型明确说明限制，以便不会把局部数据当作完整结论。
25. 作为销售计划使用者，我希望真实分析由明确配置的模型执行，以便本地演示回执不会被误认为 AI 分析。
26. 作为销售计划使用者，我希望模型配置缺失、认证失败或限流时得到可理解的提示，以便修复配置或稍后重试。
27. 作为销售计划使用者，我希望能中止分析并看到实际完成、失败或取消状态，以便不会把中断的回答当作完整结果。
28. 作为销售计划使用者，我希望重复点击同一次分析操作不会创建多份会话或重复模型请求，以便避免重复执行。
29. 作为销售计划使用者，我希望在会话内追问已经选中的数据，以便继续理解同一份快照。
30. 作为销售计划使用者，我希望重新打开会话后看到相同的数据快照和分析结果，以便回顾当时的判断依据。
31. 作为销售计划使用者，我希望历史分析保留当时版本和查询时间，以便后续业务数据变化不会改写既有记录。
32. 作为销售计划使用者，我希望分析过程不执行审批、修改或写回，以便先完成只读业务验收。
33. 作为部署者，我希望 GEA 登录凭证和模型凭证不出现在页面、会话、错误详情或公共测试材料中，以便业务身份与分析内容保持分离。
34. 作为维护者，我希望演示回放、真实 GEA 查询和真实模型验收分别报告，以便可以判断每项能力实际验证到了哪一步。
35. 作为维护者，我希望在不依赖生产权限和真实账号的情况下运行主要回归场景，以便稳定验证插件升级。

## Implementation Decisions

- **交付与兼容性。** 业务实现位于独立插件工程，个人 fork 的 Issue 用于跟踪规格和交付；不向 dsh 上游提交业务代码。插件使用明确的包版本、可搬迁的配置和官方 dsh CLI/profile 启动，不修改 dsh 源码或安装后的依赖文件。初始兼容基线是已实测的 `@deepseek-ai/dsh@0.1.5-rc.1`；仓库当前源码与该发布产物分别记录，升级需重新验证。
- **模块职责。** 外部 Client 负责页面、选择状态、数据范围预览与 Session 导航；外部 Host 负责身份、固定业务请求、响应解析、错误处理和分析快照。真实模型路由通过现有 LLM capability 配置，演示回执作为显式测试配置保留。模块只在职责需要时拆分，不为每个请求建立新的 Service Definition。
- **已有扩展点。** 页面使用现有 sidebar/main 插槽，Client 与 Host 使用已验证的认证 Fetch 接口，分析通过标准 Session 创建和 prompt 提交进入 agent loop。沿用可释放的 Cordis 注册和 locale-owned 文案。首版不以桌面 transport 或专用类型化 RPC 作为交付前提。
- **运行范围。** 首版面向本机单人使用，沿用 dsh 的浏览器认证及 Host/Origin 校验。环境、分页和超时等部署差异使用已验证的配置项；不接受浏览器提供任意上游 URL、凭证或 HTTP 方法。
- **GEA 身份。** 使用现有扫码和身份校验协议，业务请求使用已验证的用户与租户上下文。GEA access token 只存于服务进程内存，失效、切换环境或重启后重新登录；不从另一个 AionUi/AionCore 进程复制登录令牌。二维码过期与登录失效分别处理。
- **业务接口。** 以现有 AionUi/AionCore 的 GEA 读协议为参照，覆盖销售周期、计划列表、计划详情、版本列表和指定版本的 SKU 明细。筛选、分页、字段及状态含义须由实际接口与现有消费者确认；不得根据接口名称自行发明字段或扩大取数范围。首版延续原型的直接 GEA 读取方式，不新增 AionCore 运行时身份桥接依赖。
- **只读限制。** GEA 业务适配器仅暴露上述固定查询操作，不注册 actions、保存、修正、审批或 DMS 写回操作。分析使用专用 agent preset，通过已有配置限制为快照分析需要的能力，不继承通用编码 agent 的任意 Shell、网络或文件修改能力。认证和模型协议的 HTTP 方法不等同于业务写入。
- **字段忠实性。** 业务标识、数量和金额在网络解析时保留准确文本；参与确定性计算时使用保持十进制精度的实现。缺失字段保留缺失状态；展示已确认的状态名称及原始状态码，不将已观察到的 Y 类型改称 M 类型，也不推断未返回的修正字段。
- **查询与选择。** 页面保存当前环境、查询条件、计划和版本的关联关系，过期响应不得覆盖当前选择。重新查询失败、退出有效登录或切换环境时，使旧的待发送快照失效。列表、详情和 SKU 返回不完整时明确标注范围，不拼接不同版本或环境的结果。
- **分析快照。** 每次显式分析操作生成固定快照，包含来源环境、查询时间、计划及版本标识、查询条件、已取数据、覆盖范围与缺失项。Host 核对选中记录与已取得的数据一致；不能仅凭列表行号跨查询复用选择。数据超过模型输入预算时明确收窄并展示范围，不静默截断后声称覆盖完整计划。
- **Session 与持久化。** 使用现有 user/message 将快照及分析任务写入 Session，使模型可见内容可从日志重建；真实模型输出通过正常 assistant/message 或失败、取消的已有事件路径持久化。首版不新增 Session 格式或自定义事件类别，不建立第二套聊天存储，也不改写历史快照。
- **真实模型接入。** 优先复用 dsh 已有且与目标模型服务协议兼容的 Service Provider；只有兼容性验证证明需要时，才通过现有 LLM Service Definition 实现外部 provider adapter。具体 provider、model 和凭证来源以部署配置和实测为准，不把 GEA 登录 token 当作模型 Secret。缺少配置时明确失败，不隐式退回演示回执或其他模型。
- **分析呈现。** 回答围绕选中的计划数据解释数量、金额等差异，标注依据和覆盖范围，保留未知或不足以判断的情况。计划字段中的文本是业务数据，不能成为执行其他操作的授权。流中断、取消和失败保留真实状态；HTTP 成功或出现首段文本不代表分析完成。
- **错误与凭证。** 分别呈现登录过期、业务权限拒绝、网络或服务错误以及模型调用错误。诊断信息只保留有界的错误码、原因和关联标识并脱敏；不展示任意上游响应。真实会话可保存用户选择的业务数据，公共 Issue、测试 fixtures 和日志样例不携带真实业务记录或凭证。
- **实施顺序。** 先完成独立插件配置和身份状态，再迁移只读列表与详情，随后接入真实模型，最后完成测试环境全流程验收。每一步产出可运行行为及对应回归证据，不以生产环境授权修复作为测试环境实现的前置条件。

## Testing Decisions

- **主要测试入口。** 以真实启动的已安装 dsh Web profile 为最高层入口，从页面操作开始，经外部插件、标准 Session 与模型请求，最终核对页面结果和持久化读回。沿用原型已经走通的流程，不建立新的 dsh 核心测试接口，不以直接调用组件内部状态或手工拼装 Cordis context 代替产品验收。
- **回归中的替换范围。** 确定性回归仅在外部 GEA HTTP 服务和 LLM provider 响应处使用受控输入；页面、插件装载、认证 Fetch、Session、agent loop 和持久化使用实际产品实现。这些是现有集成接口，不新增平行的业务执行路径。
- **测试质量。** 断言用户可观察的状态、外部收到的请求、实际模型输入及独立读回的持久化事实。不得仅搜索助手自述的“成功”或检查内部 helper 是否被调用；模型复述某个摘要不能单独证明它读取了正确数据。
- **被测职责。** 同一主流程覆盖插件装载、Client 查询与选择、Host 身份及 GEA 数据转换、Session 交接、真实或回放 LLM provider、结果恢复。难以在该层精确覆盖的十进制处理、错误脱敏和网络响应解析可补充少量聚焦测试，不重复实现细节。
- **查询场景。** 覆盖周期、筛选、分页、详情、版本和 SKU，包含空返回、缺失字段、未知状态、精确小数、大数标识、部分数据，以及快速切换选择造成的响应乱序。证明不同版本、查询和环境的数据不会混用。
- **身份与失败场景。** 覆盖未登录、二维码过期、登录失效、业务 403、上游超时或非 JSON 错误，以及 dsh 未认证和外站 Origin 拒绝。真实查询失败后不能发送旧演示记录或上一份业务快照。
- **模型与只读场景。** 覆盖配置缺失、模型认证错误、限流、流中断、取消与显式重试；记录实际请求以确认使用所选快照。由外部请求记录证明没有调用业务写接口，且专用分析 preset 不暴露能间接修改业务的工具；不能只断言页面没有审批按钮。
- **历史与回放。** 为非平凡页面和模型输出添加脱敏、无密钥的 recorded-session 回放及对应 Web 预期，复用 dsh 的 Session snapshot/replay 机制。会话存储版本由所固定的 dsh 版本拥有，不修改已提交的历史格式样本。测试资源与 fixture 留在外部插件工程，不为业务场景修改 dsh 源码。
- **测试先例。** 原型的认证 HTTP 黑盒检查、Host 交接与实际模型请求核对、Session 摘要及磁盘读回是直接先例；dsh 的 Web queue-actions recorded-session 场景、Session snapshot/replay 支持和 LLM provider e2e 展示了已有装配与验收方式。复用时先确认它们在固定发布版上的可用接口。
- **真实验收。** 使用测试 GEA 独立登录，并通过明确配置的真实模型完成“查询 → 详情及版本/SKU → 选择范围 → 分析 → 重开会话”。验收记录实际 dsh/插件版本、环境、数据范围、模型路由和完成状态；对比页面、实际模型输入及持久化快照。真实环境凭证缺失时该验收标为未执行或受阻，不能由模拟通过代替。
- **恢复与复现。** 增加真实业务会话在新服务进程中的读回验证，并确认 GEA 登录按设计失效。测试使用独立 Harness home、工作区和动态分配的端口，按所有权清理资源；不影响用户当前原型服务或其他工作区。
- **完成条件。** 固定版本的插件可独立安装启动；上述只读交互与真实分析可用；必要负向场景及无密钥回归通过；测试 GEA 与真实模型的完整验收通过；业务读写限制、数据来源和未知项均可核对。正式环境结果单独报告。

## Out of Scope

- 销售计划编辑、修正、保存、审批、驳回、提单及 DMS 写回。
- 自动审批、后台自主取数或跨计划批量分析；首版分析以用户明确选中的单个计划及版本为范围。
- 生产 GEA 权限与组织范围修复，或通过更换租户、账号和令牌绕过现有授权。
- 完整复刻 AionUi 的所有页面与业务；通知、语音、更新策略、桌面安装包和发布链路。
- AionCore 进程间身份桥接、通用 MCP 工具迁移以及新增业务能力 Service Definition。
- 桌面 transport、通用跨端 RPC 兼容性及修改 dsh agent loop、Session 格式或其他核心源码。
- 多人共享 Host、多租户 SaaS 部署、GEA 登录凭证跨进程持久化。
- 当前接口未提供的字段、未经确认的状态映射或新建服务端 API。

## Further Notes

2026-09-10 的原型验证使用未修改的 `@deepseek-ai/dsh@0.1.5-rc.1`，测试环境真实查询、选中记录进入 Session、本地模型请求回执和磁盘读回一致。浏览器刷新后真实会话正常恢复；当时的服务重启恢复实测使用演示会话，因此本规格要求补充真实会话的新进程恢复验收。

原型中的本地回执不进行外部推理，不能作为本规格的真实 AI 分析验收。正式环境此前身份查询成功，但销售计划业务接口返回授权拒绝；测试环境成功未证明正式环境授权已恢复。

原型已验证 Web 认证 Fetch；专用 RPC 注册当时遇到发布版依赖问题，尚未完成桌面适配验证。因此首版保持已验证的 Web 路径，不能据此承诺所有 AionUi 功能或桌面场景都无需改进 dsh 扩展点。
