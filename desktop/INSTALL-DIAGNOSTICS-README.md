# Windows 安装诊断（一次运行）

1. 完整解压诊断 ZIP 到本地文件夹，不要在 ZIP 内直接运行。
2. 保存工作，退出 GEA。保持安全软件的原有设置。
3. 双击 `run-install-diagnostics.cmd`。工具先校验随附 EXE，再打开正常安装界面；按平常方式覆盖安装。
4. 安装完成页取消勾选“运行 GEA”，点击完成。采集窗口会自动生成 `GEA-report-日期-编号-snapshot-数字.zip`。
5. 发回生成的日志 ZIP。无需再手工找临时目录中的日志。

## 同盘移动候选（2026-09-27）

带 `fast-transfer` 名称的诊断包复用 0.0.22 的应用内容，只改变安装阶段的文件搬运，尚未通过 Windows 10/11 真机验收，不代表正式发行版或插件升级。仅在那台慢机器上做一次受控验证，不向同事批量推广。

该包会先自动运行隔离自检：128 个小文件的完整移动、已有目录与占用文件的复制回退、同盘暂存失败及长路径时的原路径回退。自检仅写临时测试目录；失败或超时会保留报告并停止，不开始安装。

新路径在安装目录内创建本次专属暂存目录，完整解压后逐个移动顶层文件/目录；移动不覆盖已有目标。构建时计算包内最长路径，额外暂存层可能超过 MAX_PATH 时使用原临时目录及复制路径。仍有残留时执行原来的 `CopyFiles`、重试和最终解压兜底。不会把整个安装描述为事务，也没有新增旧版本自动恢复承诺。登录、会话及工作区仍由原流程保留。

新增阶段：`move-new-entries`、`transfer-result needsCopy=0/1` 和 `install-stage-cleanup`。`needsCopy=0` 表示无需再次复制；若为 1，报告应同时出现 `copy-files`。解压、旧版卸载及防护扫描本身仍会耗时；未获得实测前不承诺分钟数。安装完成到点击“完成”的停留与进程退出清理要分开计算。

如果安装卡住，在黑色采集窗口按 S 可立即生成当前日志包，安装仍继续；按 Q 可结束采集并生成日志包，同样不会强行终止安装。不要直接关闭黑色窗口。最多采集 60 分钟，届时保存日志，不结束安装进程。原始日志实时写入同名目录，断电/意外关闭时仍可把这个目录压缩发回。

采集内容：系统版本、CPU/内存、磁盘类型及剩余空间、安全软件名称/状态、安装器和相关子进程的 CPU/读写计数、全机磁盘活动，以及安装各阶段起止/失败重试。全机磁盘计数不能完全归因于安装器，安全软件活动也不自动等于拦截证据。

不读取业务文件、账号、密码、命令行或会话，不关闭防护，不删除旧日志，不自动上传。新 EXE 仍执行正常覆盖安装流程。采集权限不足的项目会在 collection-errors.jsonl 标明，其他项目继续。

阶段包含：初始化、开始安装、检查正在运行的程序、卸载旧版及执行重试、提取内置归档、7z 解压、复制文件及重试/回退、缓存安装包、生成卸载器、注册表、快捷方式、成功/失败、界面关闭。NSIS 自身的最终临时目录清理由界面关闭时间到进程退出之间的采样推断，未替换其内部清理实现。

日志中的 `errors=1` 是该时刻 NSIS 的内部标记，初始化时也可能出现，不等于安装失败；需要结合阶段、重试及最终退出结果判断。自动化用静默安装验证采集链路，正常交互界面及 Windows 10/11 的真实性能仍以本次人工采集为准。


## 完整目录与 ASAR 候选（0.0.23）

`directory-layered` 候选使用本轮新壳与核心分层，不同于前述只改搬运的 fast-transfer 0.0.22。默认先在临时目录运行生产目录切换函数的四项探针：首装、旧版替换、提升源缺失时恢复、文件占用时保留旧版。探针失败停止安装；本机只完成编译，Windows 执行结果以报告为准。

覆盖安装前保存工作并退出 GEA。安装完成后可单独启动，核对登录、会话、工作区；健康启动约 15 秒后会清理无引用自动插件版本。未知 staging 和手动/固定版本保留。新候选未签名、未发布频道；0.0.23 在线插件兼容清单未推进。共享层创建后旧壳不能直接运行它，回退到旧 EXE 前需先选择兼容的完整插件版本。

新阶段为 `directory-stage`、`sevenzip-extract`、`directory-promote`、`old-directory-cleanup`、`install-complete`。只有安装成功后才清除本次 `.old`，因此不是新 EXE 启动失败后的自动程序降级机制。
