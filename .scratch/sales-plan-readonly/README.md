## 拆分与依赖

| 编号 | 标题 | 直接阻塞项 | 独立交付 |
| --- | --- | --- | --- |
| 01 | 独立安装后跑通登录、单页查询与 Session 读回 | 无 | 新目录可运行既有完整验证链路；完成后续最小整理 |
| 02 | 登录过期后恢复查询，并隔离不同环境的数据 | 01 | 失效、重登和环境变化后恢复查询与安全交接 |
| 03 | 按周期筛选和分页，并发送准确的计划记录 | 01 | 任意当前查询页的选中记录准确进入 Session |
| 04 | 查看计划详情和版本，并保留所选数据到 Session | 01 | 从已有单页入口查询详情、版本并交接快照 |
| 05 | 查看版本 SKU，并预览可发送的数据范围 | 04 | 明细、范围预览与持久化快照一致 |
| 06 | 用真实模型分析选中的单条计划快照 | 01 | 现有单记录路径完成真实只读分析与追问 |
| 07 | 正确处理分析中断、取消与显式重试 | 06 | 模型异常和用户取消的历史状态可核对 |
| 08 | 交付包含版本和 SKU 的可追溯真实分析 | 02、03、05、07 | 查询至完整分析、输入预算和新进程恢复验收 |

01 完成后，02、03、04、06 不互相阻塞。04 不依赖 03，因为现有单页列表已可选择计划；06 不依赖 04/05，因为先分析已有单记录就能验证模型兼容性。08 只列直接依赖，不重复列出已由它们传递覆盖的 01、04、06。

各票都从真实启动的 dsh Web profile 验证其用户流程，只在外部 GEA 与模型服务使用受控响应；无密钥回归随功能交付，真实模型和完整业务验收分别归 06 与 08。详细正文每票单独保存，发布时把本地编号替换为实际 Issue 引用。
