# 03：按周期筛选和分页，并发送准确的计划记录

## What to build

用户选择销售周期和接口支持的筛选条件、翻页查看计划，并把当前结果中明确选中的记录送入 Session。列表、查询条件和会话快照一致，用户能看清返回总数、当前覆盖范围及缺失信息。

## Acceptance criteria

- [ ] 对照现有 GEA 协议和 AionUi/AionCore 消费者确认销售周期、计划类型/状态筛选与分页参数，仅暴露实际支持的条件，不以通用交互待办接口替代销售计划列表。
- [ ] 页面支持周期选择、筛选和翻页，展示当前查询条件、总数及页范围，区分加载、空结果、权限拒绝与服务故障。
- [ ] 列表展示已提供的计划/版本、组织/经销商、类型、状态、数量、金额和更新时间；缺失值不补造，未知状态保留原始码，不将 Y 类型改称 M 类型。
- [ ] 网络响应中的业务标识和十进制文本精度从列表保持到 Session；不能因 Number 转换丢失大数或小数信息。
- [ ] 切换周期、筛选和页码会更新选择及快照有效性；乱序响应不会覆盖新查询，查询失败后不能发送旧结果。
- [ ] 从任意已返回页选择记录后，Session 的标准 user/message 包含对应来源、查询条件、记录标识和精确内容，实际模型输入与持久化读回一致。
- [ ] 使用真实 profile 加受控外部 HTTP 响应验收多页、空页、过滤、乱序、权限拒绝、缺失字段和精确数值；补充相关无密钥 Session 回放及页面预期。
