# 02：登录过期后恢复查询，并隔离不同环境的数据

## What to build

用户遇到二维码过期、登录失效或配置切换环境时，能理解当前状态、重新扫码并恢复只读查询；旧身份、旧查询结果和待发送快照不会沿用到新环境或新登录中。沿用现有扫码和身份校验协议，登录只在当前服务进程内有效。

## Acceptance criteria

- [ ] 页面区分未登录、等待扫码、二维码过期、已登录和登录失效；二维码过期后可以获取新二维码，旧轮询的延迟结果不会覆盖新登录。
- [ ] 业务认证失效时清除有效身份和待发送快照，阻止新的受保护查询，并引导重新登录；业务权限 403 不被误判为未登录或空列表。
- [ ] 更换 GEA 环境配置并重新启动后，页面显示新环境，必须独立登录；不复制另一个环境或另一个 AionUi/AionCore 进程的 token。
- [ ] 登录与环境变化使旧查询失效；延迟到达的旧响应不得重新填入页面或成为可发送数据。
- [ ] 重新登录后可再次查询计划并发送新的来源明确快照到 Session；旧 Session 的历史数据保持原样。
- [ ] 使用实际 Web profile 的回归覆盖二维码过期、401、业务 403、重新扫码、延迟响应和环境切换，断言页面、上游请求与 Session 中的数据一致且不含凭证。
- [ ] 为变化的用户状态增加脱敏 Web 预期和必要的 Session 回放，不依赖固定等待或真实二维码存活时间完成自动回归。

## Blocked by
