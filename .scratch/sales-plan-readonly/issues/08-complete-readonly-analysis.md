# 08：交付包含版本和 SKU 的可追溯真实分析

## What to build

用户完成“独立登录 → 周期/筛选/分页 → 计划详情 → 所选版本 SKU → 预览分析范围 → 真实模型分析 → 新进程重开会话”的完整流程。将已实现的查询快照与真实模型路径整合，交付首版可用的只读插件，并补齐真实业务会话的服务重启恢复证据。

这张任务包含实际整合与用户可见的数据范围处理，不是把前面任务的测试延后到最后统一编写。

## Acceptance criteria

- [ ] 从筛选或任意已返回页打开计划，在同一选择中取得详情、版本和 SKU，分析预览与实际送入模型的数据范围一致；不存在跨环境、跨计划或跨版本混合。
- [ ] 将第 05 张任务的完整快照接入真实模型流程，保留来源、查询条件、查询时间、计划/版本身份、SKU 覆盖和缺失项，而不是退回只分析列表行。
- [ ] 根据选定模型的实际输入预算检查快照与会话输入；超限时提示用户收窄并重新确认范围，不能静默截断或切换模型后声称完整分析。
- [ ] 真实分析只基于明确选中的输入，回答保留依据和未知项；原始快照、实际模型输入及会话读回可独立比对，分析过程中没有业务写请求或可间接写入的工具。
- [ ] 在测试 GEA 和真实模型上完成全流程，并重启由本次验收拥有的服务进程：历史真实业务快照与分析仍可读，GEA 登录状态按设计失效，不影响用户现有原型或其他工作区。
- [ ] 补充整合新增的无密钥 recorded-session/Web 场景和必要负向回归；沿用前面各票已经通过的聚焦检查，仅在改动或失败需要时重复。
- [ ] 用同一明确版本的插件和 dsh 发布产物复现安装与验收，记录环境类别、数据覆盖、模型路由、检查结果和剩余限制；区分模拟回放、真实 GEA、真实模型和新进程恢复四类证据。
- [ ] 未执行或受阻的真实验收保持未完成，不把正式环境 403 当成已修复；公共交付说明只记录脱敏结论，不包含内部地址、真实业务记录、用户身份或凭证。
- [ ] 最终仍为外部 Web 插件，dsh 源码和安装依赖未被修改；不包含审批、修正、保存、DMS 写回、桌面发布或 AionCore 身份桥接。

## Blocked by

- 02：登录过期后恢复查询，并隔离不同环境的数据。
- 03：按周期筛选和分页，并发送准确的计划记录。
- 05：查看版本 SKU，并预览可发送的数据范围。
- 07：正确处理分析中断、取消与显式重试。
