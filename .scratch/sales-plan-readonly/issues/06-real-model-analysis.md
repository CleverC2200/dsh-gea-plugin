# 06：用真实模型分析选中的单条计划快照

## What to build

用户在现有单页计划入口选择一条记录，明确确认输入范围后，用配置的真实模型解释数量和金额差异，在标准 dsh Session 中看到可追溯的回答并继续追问。这个最小分析流程不等待详情、SKU 或分页完成，以便尽早验证模型服务兼容性。

## Acceptance criteria

- [ ] 通过已有 LLM capability 接入显式配置的 provider/model，优先使用现有兼容的 Service Provider；只有实测证明不兼容才实现外部 provider adapter，不修改 dsh 核心。
- [ ] 模型凭证与 GEA 登录身份分别配置，缺失、错误或不兼容配置给出明确诊断；不把 GEA token 当模型 Secret，不自动退回本地回执或其他模型。
- [ ] 点击分析创建标准 Session 并提交计划快照和任务；页面与会话清楚区分真实分析和显式演示回执。同一次正在提交的操作不会因重复点击创建多份会话或请求。
- [ ] 分析专用 agent preset 只提供快照分析需要的能力，不继承任意 Shell、网络、文件修改或业务写工具；业务字段中的文字不作为执行其他操作的授权。
- [ ] 回答围绕实际快照，区分源数据、计算结果、推测及缺失依据；确定性计算保持十进制精度，不对未取得的详情或 SKU 声称完整分析。
- [ ] 标准 user/message 保留全部模型可见业务输入，模型回答通过已有成功/失败事件持久化；实际请求和历史快照可独立核对，用户可在同一 Session 内追问该快照。
- [ ] 产品回归使用受控 LLM 响应证明精确输入、模型路由、持久化输出、重复点击和只读能力；增加无密钥 Session 回放，不仅检查模型复述的摘要。
- [ ] 用测试 GEA 的真实记录和明确配置的真实模型完成一次单记录分析，记录实际路由和完成状态；凭证或服务不可用时保持未验收，不以本地回执代替。
