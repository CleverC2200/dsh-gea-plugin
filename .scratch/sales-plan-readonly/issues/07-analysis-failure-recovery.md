# 07：正确处理分析中断、取消与显式重试

## What to build

用户在真实分析过程中遭遇限流、认证失败或流中断时，可以看到实际状态、中止或显式重试，并在重新打开会话后区分完整回答与未完成尝试。沿用 dsh 的既有生命周期和持久化能力，只补齐插件实际缺失的配置或用户流程。

## Acceptance criteria

- [ ] 模型认证失败、限流、配置错误和流中断提供有界且脱敏的原因；HTTP 200、首段文本和部分输出不等于完整完成。
- [ ] 用户可以通过已有 Session 操作取消分析，取消后不显示完成标记；释放本次请求资源，不自动启动新的分析。
- [ ] 显式重试保留原始快照或让用户明确重新选择新快照；不会静默重查并替换当时数据，也不会将多次尝试拼成一份成功结果。
- [ ] 尊重已有 provider 重试策略，不额外引入重复执行循环；快速重复点击或取消/完成竞争不会创建额外会话或未请求的模型调用。
- [ ] 会话重新打开后仍能分辨成功、失败、取消及重试历史；使用已有 durable events，不修改 Session 格式或隐去失败记录。
- [ ] 使用真实 profile 和可控制完成时点的外部 LLM 响应覆盖认证失败、限流、200 后流中断、取消和显式重试，核对外部请求数、页面与持久化状态；新增对应无密钥 Session 回放。
